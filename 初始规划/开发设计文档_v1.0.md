## 2 模块接口定义

### 2.1 策略基类

```python
# strategy/base.py

class StrategyBase(ABC):

    @property
    @abstractmethod
    def name(self) -> str:
        """策略名称，对应 strategy_config.strategy_name"""

    @property
    @abstractmethod
    def params_schema(self) -> dict:
        """参数 JSON Schema，用于飞书调参时的校验"""

    @abstractmethod
    def calculate(self, df: pd.DataFrame, params: dict) -> List[Signal]:
        """
        df 列要求: trade_date, open, high, low, close(=close_hfq), volume
        df 按 trade_date 升序排列，至少包含该股全部历史日线数据
        返回: Signal 列表（可以为空）
        """

    @abstractmethod
    def default_params(self) -> dict:
        """默认参数，与 strategy_config 初始 INSERT 一致"""

    def min_data_points(self) -> int:
        """该策略最少需要多少个交易日数据，默认0（由子类覆盖）"""
        return 0
```

### 2.2 数据采集类

```python
# crawler/baostock_crawler.py

class BaostockCrawler:
    """统一数据采集器。通过 baostock SDK 批量拉取全市场数据（生产级）。

    数据覆盖：沪深 A 股全量日K线、复权因子、基本面、行业分类、股票基础信息。
    北交所：baostock 不支持（query_stock_basic 无 bj. 前缀股票，bj./sh./sz. 前缀均返回 0 行）。
    采集方式：按股票代码逐一查询 baostock API（非逐日下载交易所文件）。
    仅查询 A 股（type=1），自动排除指数/可转债/ETF。
    """

    def login(self) -> bool:
        """baostock 登录，带 5 次重试。"""

    def logout(self):
        """baostock 登出（bs.logout()）。"""

    def get_a_stock_codes(self) -> Dict[str, dict]:
        """获取全量A股代码及基础信息（仅 type=1，排除指数/可转债/ETF）。
        Returns: {code: {name, ipo_date, out_date, status}, ...}
        自动跳过 CUTOFF_DATE 前退市的股票。"""

    def get_all_stock_codes(self) -> List[str]:
        """兼容旧接口，返回纯代码列表。"""

    def download_all_stocks(self, start_date: str, end_date: str,
                            skip_existing: bool = True) -> dict:
        """全量历史日K线下载，支持 DB 去重跳过 + 会话失效自动重登录。"""

    def download_daily_update(self, trade_date: date = None, db=None) -> dict:
        """每日增量更新（生产级）。
        
        可靠性机制:
        - 仅查询 A 股（type=1），排除指数/可转债/ETF
        - 随机请求间隔（0.3~0.7秒），避免限流
        - 指数退避重试（最多 4 次，基础 3 秒）
        - 会话失效（用户未登录）自动重新登录并重试
        - 批量 INSERT（200行/批），提升写入性能
        - 自动从 stock_master 填充 stock_name
        - 失败记录写入 failed_downloads 表供补采
        - 跳过当日已有数据的股票 + 当日尚未上市的股票
        
        Returns: {rows, stocks, errors, skipped, failed_codes, elapsed_seconds}
        """

    def download_for_date(self, trade_date: date, db=None) -> dict:
        """补采指定交易日数据（与 download_daily_update 相同逻辑）。"""

    def get_stock_basic_info(self) -> pd.DataFrame:
        """获取全量股票基础信息。"""

    def download_fundamentals(self, codes: List[str] = None,
                              skip_existing: bool = False,
                              skip_pe_pb: bool = True) -> int:
        """基本面数据下载（PE/PB/ROE/增长率/行业）。"""

    # 内部方法
    def _fetch_kline(self, bs_code, start_date, end_date) -> tuple:
        """带重试的K线下载，返回 (rows_or_None, need_relogin)。"""

    @staticmethod
    def _batch_insert_rows(db, rows_batch) -> int:
        """批量 INSERT OR IGNORE（200行/chunk）。"""

    @staticmethod
    def _record_failure(db, exchange, trade_date, data_type, error_msg, stock_code=None):
        """记录下载失败到 failed_downloads 表。"""
```

> **设计说明**：
> - 不再需要 ExchangeCrawler 抽象基类及 SSE/SZSE/BSE 三个子类，因为 baostock 已封装了交易所差异
> - 断点续传通过 `data/download_progress.json` 进度文件 + DB 中已有股票集合双重判定
> - 基本面数据通过三个 baostock API 获取：`query_history_k_data_plus`（PE/PB）、`query_profit_data`（ROE）、`query_growth_data`（增长率）
> - **北交所不支持**：baostock 不包含北交所股票，`stock_master` 中 318 只 BSE 记录来自基本面爬虫，`daily_quote` 中无北交所日线数据。后续可考虑用 akshare 补采。

@dataclass
class Signal:
    stock_code: str
    stock_name: str

## 3 数据库 Schema 管理

### 3.1 当前方案：init_db 裸 SQL（无版本迁移）

当前使用 `app/db/schema.py` 中的 `init_db()` 函数在应用启动时执行 DDL，幂等可重复执行：

```python
# app/db/schema.py
def init_db(sync_session) -> None:
    """初始化数据库：建表 + 默认数据。幂等，可重复执行。"""
    for name, sql in ALL_TABLES:
        for stmt in sql.strip().split(";"):
            ...
    sync_session.execute(text(DEFAULT_STRATEGY_CONFIG))
    sync_session.commit()
```

建表顺序（按依赖关系）：

```
1. trade_calendar          ← 无依赖
2. stock_master            ← 无依赖
3. daily_quote             ← 无依赖（但逻辑上依赖 trade_calendar）
4. index_daily_quote       ← 无依赖
5. corporate_actions       ← 无依赖
6. portfolio               ← 无依赖
7. portfolio_history       ← 无依赖
8. signal_history          ← 无依赖
9. strategy_config         ← 无依赖
10. strategy_param_log     ← 无依赖
11. stock_industry         ← 无依赖
12. failed_downloads       ← 无依赖
13. stock_fundamentals     ← 无依赖
14. system_metrics         ← 无依赖
```

### 3.2 计划方案：Alembic 迁移

未来引入 Alembic 后，初始迁移一次性创建所有表：

```bash
alembic revision --autogenerate -m "init_all_tables"
```

> **为何当前不用 Alembic**：开发环境用 SQLite，生产用 PostgreSQL，Alembic 的 autogenerate 在不同数据库间行为差异大。且单用户场景下 Schema 变更频率极低，`init_db` 加手动 DDL 足以满足当前需求。

## 6 关键设计决策

### 6.1 FastAPI 进程模型

单进程 + uvicorn（不用 gunicorn + 多 worker）。原因：单用户场景 QPS < 1，多 worker 只会浪费内存。飞书 Webhook 和 REST API 共用同一进程，uvicorn 的 async 足够处理并发。

### 6.2 数据库连接

- **开发环境（SQLite）**：
  - FastAPI：`aiosqlite`（异步），单连接（SQLite 不支持并发写入）
  - Crawler/Strategy：`pysqlite`（同步），单连接
  - 优势：零配置启动，无需 Docker。劣势：不支持 `NOW()`、JSON 函数、并发写入
- **生产环境（PostgreSQL）**：
  - FastAPI：`asyncpg`（异步），连接池 min=2 max=10
  - Crawler/Strategy：`psycopg2`（同步），连接池 size=2
- **连接切换**：通过 `DATABASE_URL` 环境变量自动识别，`_is_sqlite = "sqlite" in settings.DATABASE_URL`

### 6.3 策略计算触发

不走消息队列。`daily_crawl.sh` 采集成功后直接 `python3 strategy/daily_strategy.py`。单用户场景不需要解耦，同步调用最简单可靠。

### 6.4 不引入 ORM

策略计算是全表扫描（5000 只 × 1200 行/只），ORM 的 overhead 不可接受。使用原生 SQL + pandas 批量操作。

### 6.5 选择 baostock 而非三大交易所直接下载

放弃三大交易所单独爬虫方案，统一使用 baostock 的原因：
- 三大交易所文件格式各异（SSE=CSV/GBK, SZSE=XLSX, BSE=CSV/UTF-8），解析成本高
- 交易所网站改版频繁，维护三个解析器的工作量远大于维护一个 baostock 调用
- baostock 已封装复权因子、行业分类等衍生数据，减少重复开发
- baostock 提供统一的全量股票列表 API，无需手动合并三个交易所的股票名单

### 6.6 静态 HTML 而非 Vue 3

当前前端为纯静态 HTML+JS（非 Vue 3 + Vite + Element Plus）。原因：
- 开发周期缩短，无需构建工具链
- 单用户场景下交互复杂度低，纯 JS 足以覆盖需求
- 后续如需升级为 Vue 3 架构，后端 API 接口已经就绪，前端可独立重构

### 6.5 DeepSeek vs 本地模型

选择 DeepSeek API 而非本地部署模型的原因：
- 单用户每日 10-20 次调用，API 月费 < ¥2
- 本地部署 7B 模型需要额外 4-8GB 显存，ECS 没 GPU
- Function Calling 能力本地小模型不可靠
