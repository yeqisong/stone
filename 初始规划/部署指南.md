## 2 快速部署

### 2.1 获取代码

```bash
# 将项目目录拷贝到服务器
scp -r ./stone user@server:/opt/stone
cd /opt/stone
```

### 2.2 配置环境变量

```bash
# ⚠️ 不要直接 cp .env.example .env（开发环境 SQLite 配置不适用于生产）
# 使用生产环境配置文件
cp .env.prod .env
vi .env
```

**⚠️ 关键要求：以下三处的密码必须一致！**

```bash
# 运行模式
APP_ENV=prod

# ──────────────────────────────────────────────
# 数据库配置（三个地方的密码要完全一样！）
# ──────────────────────────────────────────────

# 1. DATABASE_URL 中的密码（app 连接数据库用）
DATABASE_URL=postgresql+asyncpg://stock:你的密码@db:5432/stock_monitor
#                                       ↑ 这里写密码

# 2. DATABASE_URL_SYNC 中的密码（同步连接用）
DATABASE_URL_SYNC=postgresql://stock:你的密码@db:5432/stock_monitor
#                                    ↑ 必须与上面一致

# 3. POSTGRES_PASSWORD（docker-compose 初始化数据库用）
POSTGRES_USER=stock
POSTGRES_PASSWORD=你的密码     # ⚠️ 必须与 DATABASE_URL 中的密码一致！
POSTGRES_DB=stock_monitor

# ──────────────────────────────────────────────

# 登录认证
LOGIN_USERNAME=admin
LOGIN_PASSWORD=你的密码     # ⚠️ 务必修改
APP_SECRET_KEY=随机字符串   # ⚠️ 务必修改，openssl rand -hex 32 生成

# 飞书 Bot（可选）
FEISHU_APP_ID=cli_xxxxx
FEISHU_APP_SECRET=xxxxx
FEISHU_VERIFY_TOKEN=xxxxx

# DeepSeek AI（可选，不填则使用快捷菜单）
DEEPSEEK_API_KEY=sk-xxxxx
```

> ❗ **常见部署失败原因 #1**：`.env` 中的 `DATABASE_URL` 密码与 docker-compose 的 `POSTGRES_PASSWORD` 不匹配。
> 验证方法：检查 `docker compose logs app` 中是否有 `FATAL: password authentication failed for user "stock"`

### 2.3 启动服务

```bash
# 首次启动（含镜像构建）
docker compose up -d --build

# 查看日志
docker compose logs -f app

# 验证
curl http://localhost/health
# → {"status":"ok","database":"connected","version":"1.0.0","env":"prod"}
```


### 2.5 配置 Crontab

```bash
crontab -e
```

```
# 每交易日 17:35 自动采集数据 + 策略计算
35 17 * * 1-5 cd /opt/stone && bash scripts/daily_crawl.sh >> logs/cron.log 2>&1
```

### 2.6 访问系统

```
http://服务器IP
默认账号: admin / admin123 (请立即修改)
```

## 3 数据管理

### 3.1 数据存储

| 环境 | 数据库 | 位置 | 大小(全量) |
|------|--------|------|-----------|
| **本地开发** | PostgreSQL 15 | Docker 容器 `pgdev` 或 `stock-db` | ~2-3GB |
| **生产** | PostgreSQL 15 | Docker volume `data/pgdata` | ~2-3GB |


### 3.2 数据覆盖

| 品种 | 数量 | 日期范围 |
|------|------|----------|
| A股日K线 | 6,346只 / 656万行 | 2021-01-04 ~ 最新 |
| 上交所 (SSE) | 2,386只 | 同上 |
| 深交所 (SZSE) | 3,960只 | 同上 |
| 北交所 (BSE) | 暂不支持 | baostock 不含BSE数据 |

### 3.3 备份数据库

```bash
# PostgreSQL 备份
docker compose exec db pg_dump -U stock stock_monitor > backup_$(date +%Y%m%d).sql
```

### 3.4 从备份恢复

```bash
# PostgreSQL 恢复
docker compose exec -T db psql -U stock stock_monitor < backup_20260608.sql

# 恢复后重启
docker compose restart app
```

## 4 飞书 Bot 配置（可选）

### 4.1 创建飞书应用

1. 登录 [飞书开放平台](https://open.feishu.cn)
2. 创建企业自建应用 → 获取 `App ID` 和 `App Secret`
3. 在 `.env` 中填入 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`

### 4.2 配置事件订阅

1. 飞书开放平台 → 事件订阅 → 请求地址 URL
2. 填入 `https://你的域名/webhook/feishu`
3. 获取 Verification Token，填入 `.env` 的 `FEISHU_VERIFY_TOKEN`

### 4.3 本地调试

开发环境可用 `web/feishu_test.html` 页面模拟飞书消息，不需真实飞书配置。

## 6 故障排查

| 问题 | 检查 |
|------|------|
| 页面无法访问 | `docker compose ps` 确认 nginx 在运行；检查防火墙开放 80 端口 |
| 登录失败 | `.env` 中 `LOGIN_USERNAME` / `LOGIN_PASSWORD` 是否正确 |
| **API 返回 500 / 启动报错** | `docker compose logs app` 查看错误日志。**常见原因：`.env` 中数据库密码与 docker-compose 不匹配** |
| 数据库连接失败 | `docker compose logs db` 确认 PostgreSQL 已启动；验证 `.env` 中 `DATABASE_URL` 的密码与 `POSTGRES_PASSWORD` 一致 |
| 数据不更新 | 检查 crontab 是否配置；手动执行 `scripts/daily_crawl.sh` 看报错 |
| baostock 下载失败 | 网络连通性；baostock 偶尔限流会自动重试 |

## 7 安全建议

- [ ] 修改 `.env` 中所有默认密码
- [ ] 设置 `APP_SECRET_KEY` 为随机字符串（`openssl rand -hex 32`）
- [ ] Nginx 配置 SSL 证书（Let's Encrypt）
- [ ] 防火墙仅开放 80/443 端口
- [ ] 定期备份数据库（建议每日自动备份）
- [ ] 生产环境务必设置 `APP_ENV=prod`

### SQLite → PostgreSQL 迁移说明

如果你的本地环境还使用旧的 SQLite 数据库，按以下步骤迁移：

```bash
# 1. 确保本地 PostgreSQL 已启动（已有 pgdev 容器则跳过）
docker run -d --name pgdev \
  -e POSTGRES_USER=stock \
  -e POSTGRES_PASSWORD=test123 \
  -e POSTGRES_DB=stock_monitor \
  -p 5432:5432 \
  postgres:15-alpine

# 2. 临时用 SQLite 配置导出数据
cp .env .env.bak
# 修改 .env 中的 DATABASE_URL 改为 SQLite
# DATABASE_URL=sqlite+aiosqlite:///./data/stock_monitor.db
# DATABASE_URL_SYNC=sqlite:///./data/stock_monitor.db

python3 scripts/export_dump.py
# → 生成 data/stock_monitor_dump.sql.gz

# 3. 恢复 PostgreSQL 配置
cp .env.bak .env

# 4. 导入 PostgreSQL
zcat data/stock_monitor_dump.sql.gz | psql -U stock -d stock_monitor -h localhost

# 5. 验证
psql -U stock -d stock_monitor -h localhost -c "SELECT COUNT(*) FROM daily_quote"
# → 6562295

# 6. 迁移完成后可删除 SQLite 以节省空间
rm data/stock_monitor.db
```
