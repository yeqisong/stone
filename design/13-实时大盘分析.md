# 13 · 实时大盘分析页设计

> v3.25.0（2026-11-27）。注：design/13 编号与 tag 序列独立；初稿误写 v3.24.0，该 tag 已被并行会话的图表手势功能占用，按 git tag 现实改 v3.25.0。大盘页 `#/k` 全部是日K趋势分析，本设计补「当前盘面」视角：
> 新增子页面 `#/kr`（实时盘），聚合宽度、情绪轨迹、指数分时、量能、涨停梯队、
> 板块雷达与大盘资金分时。挂 `research.market.view` 父节点，无新权限码。

## 1. 需求与设计原则

- **入口形态**：大盘页子页面（hash `#/kr`），不加一级导航项（导航栏已有 9 个一级 tab）。
  入口 = 大盘页工具栏「⚡ 实时盘」按钮；`subTabPerms.kr = 'research.market.view'` 门控。
- **刷新模型**：后端单后台线程周期刷新内存缓存（默认 60s，`strategy_config.market_realtime`
  可调），HTTP 端点只读缓存 + 库内 slot 重放，**端点不触发外部请求**；缓存缺源时端点
  触发一次按需刷新（`ensure_refresh_async`，90s 节流，treemap `_ensure_async` 同款模式）。
  前端 setTimeout 链轮询（交易时段 15s / 其他 60s）。
- **数据源零配额**：全部公开接口（新浪/腾讯/东财），不碰 tushare 配额。
- **不动既有口径**：10 分钟 slot 落库仍归 treemap_intraday；本模块的宽度快照只留内存。

## 2. 数据底座实测（2026-11-27，样本存 `tests/fixtures/`）

| 数据 | 源 | 实测结论 |

### 2.1 重要教训：push2his 指纹墙（当晚新增）

- trends2（push2his 域）20:13 首测全通（curl 命令行 + ndays=5 一次拿 5 天分钟线），
  20:39 起对**非命令行-curl 的 TLS 指纹**差别对待：requests / curl_cffi(impersonate=chrome)
  全部超时（读到 ~24KB 后流中断，恰为 70KB 响应的压缩体积；`--compressed` 的 gzip/br 同样挂，
  无 Accept-Encoding 的命令行 curl 始终秒回）。
- 强制 IPv4（WSL2 IPv6 出口黑洞是另一层坑：`getaddrinfo` 返回 v6 在前且 v6 ENETUNREACH）
  与 `Accept-Encoding: identity` 均不能绕过 → **弃用 push2his**，分时/量能切腾讯+新浪。
- SSE 流格式：响应带 `data: {...}` 前缀 + null 心跳行，解析取首个 data 非空 JSON
  （`em_quote._loads_json`，fflow 仍用）。
- 泛化教训：**「实测可用」有时效性**，外部接口要在解析层做形态兼容 + 单源失败不拖垮整页
  （refresh_all 单源 try/except 就是为此）。

## 3. 后端设计

### 3.1 模块与缓存

- `crawler/em_quote.py`：东财抓取唯一出口（涨停池/板块/资金分时），统一走 `em_get`
  串行闸门（1.2s+抖动）。九请求/周期 ≈12s。
- `app/market_realtime.py`：聚合层。模块级 `_CACHE`（threading.Lock）+ 后台 daemon
  线程 `refresh_all()`；`market_realtime_loop()` 挂 lifespan（照 treemap_task 模式），
  交易窗口复用 treemap 的 09:25–15:05 + `_is_trade_day`。
- 开关：`strategy_config` 行 `('market_realtime', params {"interval_s": 60})`，
  缺行即启用（`read_config` 兜底）；停用写 enabled=false，无 UI 依赖。
- 刷新实测耗时 27-83s（冷连接慢）→ 有效数据年龄 ≈ 1.5-2.5 分钟，页面以 `asof`
  标注数据时点、`stale` 标记滞后。

### 3.2 聚合函数（单测目标，`tests/unit/test_market_realtime.py`）

- `aggregate_breadth`：涨跌停阈值复用 `_limit_pct`（300/301/688/689→19.8）；停牌不进分母。
- `estimate_turnover`：新浪 5 分钟桶逐段累计，`est_full = 累计 × 近4日日均全天额 / 近4日同期均值`，
  同期缺失退化线性（48 桶口径）。
- `_merge_min5_buckets`：沪+深 5 分钟行按 `HH:MM` 桶对齐相加。
- `senti_track_from_slots`：`stock_treemap_intraday` 单 SQL `GROUP BY slot`
  （percentile_cont 中位数 + 正则前缀涨跌停阈值）→ 逐 slot `_verdict(..., 0, 0)` 三成分口径。
- `zt_summary`：连板高度/炸板率/天梯（同板位按封单额排序）/池截断（150，落库不截）。

### 3.3 日终落库与回补

- 新表 `zt_pool_daily`（PK trade_date；limit_up/limit_down/broken/broken_rate/max_lbc +
  pool/broken_pool JSONB 全量明细）。DDL 走 `ALL_TABLES` 注册，init_db 幂等建表。
- `archive_zt_daily`：交易日 15:05 后且当日无行 → 用缓存（或一次性补拉 push2ex 历史接口）
  UPSERT。**收盘后重启后端也能补当日档**（loop 每周期做幂等检查，实测两次验证）。
- `scripts/backfill_zt_pool.py`：历史回补（--start/--end，逐交易日 2 请求 ≈11min/250日）；
  正常交易日空池视为「接口无该日数据」跳过不写，防把接口故障写成历史。

### 3.4 API

- `GET /api/market/realtime`（TTL 15s）：`{asof, stale, refreshing, session, breadth, senti,
  senti_track, indices_trend, turnover, zt, boards, fflow}`。
- `GET /api/market/realtime/zt-history?days=`（TTL 300s）：连板高度历史。
- 权限：既有前缀规则 `/api/market/.* → research.market.view` 兜底，无新路由规则/权限码；
  `definitions.py` 节点 api/note 补注（同一提交）。

## 5. 口径决策（最重要）

1. **宽度双口径并存**：宽度卡用新浪全市场实时快照（秒级新鲜）；情绪轨迹用
   `stock_treemap_intraday` 10 分钟 slot（落库口径，与树图页同源）。两卡并排、各自标注，
   不互相换算。
2. **三成分轨迹与日频序列可比**：slot 重放调 `_verdict(above_count=0, index_count=0)`
   —— VWAP 项恒缺省 10 分，与 `market_sentiment_daily.score`（v3.22 口径决策）同公式；
   当前「四成分实时分」（含指数 VWAP）只在轨迹图上以虚线参考线呈现，不入序列。
3. **量能=上证综指+深证综指 amount 合计**（市场全口径），非深成指（仅 500 成分）；
   预估优先「近4日同期占比」口径，缺历史退线性。
4. **涨跌停家数两处不同源**：宽度卡的 limit_up 来自新浪快照阈值近似（565，含未封住的
   盘中触板），梯队卡的 limit_up 来自东财涨停池（417，收盘口径的封住家数）——两者天然
   不相等，卡片各自标注来源。
5. **板块雷达为东财行业口径**（一级+细分混排 496 个），与树图申万 L1 不同，不跨口径联动。
6. 北交所不进宽度口径（对齐 hs_a / 树图现状）。

## 7. 规范摘要（本模块约定）

- 东财请求一律 `em_get`；只允许 push2/push2ex 域（push2his 弃用）。
- 解析层「空结果」与「无数据」区分：列表空 = 合法状态（当日无涨停），响应体缺失 = 抛错。
- 单源失败不拖垮整页：refresh_all 每 key 独立 try/except；前端保留旧数据静默重试。
- 新表只增不改；日终档幂等（ON CONFLICT DO NOTHING + 缺行补拉）。

## 9. 批次三：盘面异动告警 + 空仓闸门联动（增补）

### 9.1 盘面异动告警（mk%）

- **指标全读内存缓存**（refresh_all 产物），评估零新增外部请求；每周期（交易窗口内）
  在刷新后跑 `evaluate_market_alerts`。
- 七类 kind（`mk_idx_surge/mk_idx_drop/mk_breadth_up/mk_breadth_dn/mk_height/mk_panic/mk_strong`，
  budget VARCHAR(20)）：指数 15min ±1.2%（side 状态切换 + 滞回复位）、宽度上穿 0.65/下穿 0.35
  （one-shot + 滞回）、连板高度 ≥5（当日一次）、情绪进 panic（critical）/strong。
  状态机惯例照搬 intraday_watch（side-transition / one-shot hot flag / 基线首轮不报）。
- **冷却 DB-backed**（`risk_alerts user_id IS NULL AND kind` 查 created_at，重启不重发）
  + mk% family 冷却 10min + 当日 cap 15；配置在 `strategy_config.market_alerts`
  （缺行 = 默认全开；`read_market_alerts` 兜底 DEFAULT_MARKET_ALERTS）。
- **WS 路由扩展**：`risk_alerts.user_id IS NULL` 的行原本只发给 `model.alerts.view` 的
  socket——`_alert_visible`（status.py，纯函数可单测）给 `mk%` 开了广播全员的分支
  （市场事件人人相关）。前端 App.vue `mk*` 通知分支点击跳 `#/kr`。
- 不进 AI 解读：intraday_ai 是个股分析器（`intraday_ai_event.user_id/stock_code NOT NULL`），
  市场级事件不适配。

### 9.2 实时空仓闸门（live_gate，仅展示）

- 调研结论：系统原有**三道互不相通**的闸门——regime 日频闸门（只在信号 DAG
  `dag_task_model_signal` 生效）、`buy_check.market_gate`（日频 EOD MA20+宽度，买入候选
  用）、`market_sentiment`（实时但仅展示）。盘中实时买入判定 `trade_intraday.state()`
  完全不看盘面。
- `compute_regime_gates` 从 pipeline 下沉到 `app/regime_gate.py`（pipeline 保留导入别名，
  test_regime_gate.py 不变）；`buy_check.live_gate(db)` 组合三源**取最严级别**
  （closed > caution > open），60s 模块缓存。
- 展示面：`/api/market/realtime` 的 `gate` 字段 + `#/kr` 顶部横幅；`/api/market_sentiment`
  附 `gate` → 情绪条 chip（覆盖大盘页+持仓页）。
- **当前不改买入行为**：candidates 的 actionable 仍是日频口径。升级路径（一行）：
  `buy_check.candidates` 的 `market_ok` 叠加 `live_gate(db)['pass']`。
