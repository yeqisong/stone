# 01 — 系统架构

> K道（Stone）· A 股个股买卖点监测系统
> 文档基准：代码版本 v3.7.0（2026-09-01 更新）；v3.3.0~v3.6.0 为模型链路强化（评估器 v2/IC 体检/超额标签/walk-forward/纸面组合），v3.7.0 为 Qlib 移植七里程碑（回测引擎 v2/TopkDropout/绩效报告/Alpha158 因子库/DoubleEnsemble）

---

## 1. 系统定位

全栈 A 股量化监测平台，覆盖：**多数据源行情采集 → 数据质量监控 → KEPL 特征引擎 + Alpha158 因子库 → XGBoost/LightGBM 模型训练与信号 → 回测引擎 v2 + 纸面组合 → 持仓/飞书 AI 助手**。**个人本地使用**：服务器部署已于 2026-08 拆除（docker + stone 数据全部清理），线上 https://s.pmlab.top 已下线，数据采集与分析全部在本机运行。

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.11 · FastAPI · SQLAlchemy（原生 SQL，无 ORM 模型） |
| 数据库 | PostgreSQL 15（asyncpg 异步 + psycopg2 同步双引擎）· Redis 7 |
| 数据源 | **TuShare 唯一主源**（限流 50次/分、8000次/天，配额表跟踪）· **Baostock 字段补充器**（ROE/营收净利、ETF 复权、交易日历）。AKShare 已于 v3.2 移除 |
| 量化 | XGBoost（**训练 GPU 优先**：CUDA 可用时 device=cuda，冒烟测试失败自动回退 CPU）· LightGBM（DoubleEnsemble 集成实验）· Optuna(TPE) · pandas/numpy（无 TA-Lib，指标纯实现） |
| 回测 | **strategy/backtest 引擎 v2**（撮合/账户/绩效三层，涨跌停/T+1/延迟结算/最低佣金/冲击成本；评估入口默认 engine=v2，v1 `_simple_backtest` 保留为兼容口径） |
| 表达式 | KEPL（Lark LALR(1) 解析器，**32 算子**，目录单一事实源 `GET /api/kepl/functions`，见 02 文档 §1.7） |
| AI | DeepSeek（OpenAI 兼容，8 个 Function Calling 工具）· 飞书 Bot |
| 前端 | Vue 3 + Vite 5 + Pinia 3 + Naive UI + ECharts + Vue Flow + Monaco Editor（详见 04 文档） |
| 部署 | 本地运行（后端 :8000 + 前端 :3000 dev）；Docker/Nginx 配置留存但已停用 |

## 5. 启动流程（app/main.py lifespan）

```
1. APP_SECRET_KEY 校验（prod <16字符拒启）
2. init_db(db)            → 建表 + 幂等迁移 + 预置数据（16内置函数/23系统特征/策略配置）
3. entity_stats 基线      → 空表时 JOIN stock_master×trade_calendar 计算（~40s，非致命）
4. 恢复异常模型           → model_versions: TRAINING→DRAFT
5. signal.set_main_loop() → 注册 asyncio 主循环（供后台线程唤醒 WS）
6. broadcast_dag_status() → WS 广播协程（事件驱动 + 2s/30s 超时兜底）
7. start_cron_scheduler() → cron 后台线程
关闭时：cancel 广播 + dispose 异步引擎
```

## 7. 认证与安全

- **JWT 单用户**：`POST /api/login`（限 5 次/分/IP）→ HS256 token（24h），前端 Axios 拦截器注入 `Authorization: Bearer`。
- **写操作端点**用 `Depends(get_current_user)`；`optional_auth` 实际同样强制。
- **WS 认证**：`?token=` query 参数（prod 强制校验，dev 放行）。
- **函数沙箱**：AST 安全扫描（封 eval/exec/getattr/__class__ 等 22 个危险名 + 递归属性链 + import）+ 子进程 `python -I` 隔离模式执行。
- **已知待办**：backfill/ai-chat 等部分端点无认证；WS token 走 query 会进访问日志。

## 9. 已知代码实况（与历史文档口径的差异）

1. **数据源架构（v3.2.1）**：TuShare 唯一主源（按交易日全市场拉取，配额表 tushare_quota 跟踪 8000次/天）；Baostock 降级为字段补充器（ROE/营收净利、ETF 后复权）+ 交易日历唯一同步源；AKShare 已删除。无多源 fallback——tushare 不可用即任务失败。
2. **采集路径统一**：DAG 节点与补数均走 tushare 适配器按日期拉（停牌股自然缺失、退市股历史天然覆盖），BaostockCrawler 高速路径/catch_up/progress.py 已删除。
3. `dag_task_model_train` 不在 NODE_FN_MAP，仅由模型 API 触发；训练函数显式接收 version 并校验状态（v3.3.0），不再取"最新 DRAFT"。
4. **model_signal（v3.3.0 起）**：≥2 个周期模型就绪时启用 ML 预测（`predict_for_version` 多周期均值 + NaN 缺失分支），否则规则评分兜底；信号层默认滤除旧版本模型的历史信号（`include_stale=true` 豁免）。
5. `functions.py` 存在 DELETE 路由装饰器堆叠 bug（L509 delete 装饰器叠在 list_versions 上遮蔽 L554 delete_function），DELETE 实际返回版本历史；正确处理函数在后但注册顺序靠前者胜。
6. 旧"每日固定 DAG 主流程"已下线，现行机制 = dag_flows 动态编排 + cron 定时触发；daily_crawl.sh 已改为触发已发布流程。
7. **GPU 训练（v3.2.1）**：`dag_task_model_train` 训练前检测（xgboost build_info USE_CUDA + 小数据冒烟测试）→ `device='cuda'`；驱动/显存异常或机器无 GPU 时自动回退 CPU 并写节点日志。推理（model_signal/health）保持 CPU。
8. **本地数据规模（2026-08-22）**：kline 2000→今补数完成（daily_quote 17,657,149 行、6454 交易日、重复 0）；index_daily_quote 634,441 行（2000 起分批续跑中）；feature_values 23 特征全量（397,765,810 行，2000-01-04 ~ 2026-08-20）；tushare 配额 8000 次/天预算约束补数节奏。**Alpha158 因子库（v3.7）**：114 因子入库，2026-09 起按年分段全量回补 2000→今（`scripts/alpha158_full.py`，断点续跑），完成后统一刷新完整度统计。
9. **回测引擎双轨（v3.7）**：评估入口默认 engine=v2（`_backtest` 统一入口返回 v1 口径 dict，total_trades 只计卖出、win_rate 按 gross_win）；ideal/seed 基线仍走 v1 引擎；纸面组合已迁 v2 内核（种子账户 + EOD 幂等）。
10. **e2e Playwright 在本机 WSL（ubuntu26.04）不可用**——tests/e2e 历史性失败为环境问题；UI 验证走 API + DOM 事实 + 前端构建检查。
