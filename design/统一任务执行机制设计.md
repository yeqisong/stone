> 版本: v1.0  
> 创建: 2026-07-15  
> 状态: 设计阶段

---

## 1. 背景与目标

### 1.1 现状

当前系统存在三套各自独立的任务执行机制：

| 机制 | 位置 | 状态 |
|------|------|------|
| DAG 流程执行 | `app/api/dag_flows.py:execute_flow` + `scripts/dag.py:DagExecutor` | ✅ 可用 |
| 特征补数 | `app/api/features.py:_run_compute` + `_compute_tasks` | ✅ 可用 |
| 历史补数 | `crawler/backfill.py:BackfillManager` | ✅ 可用 |

三者各自管理自己的任务状态、进度、WS 推送逻辑，代码重复度高。

### 1.2 目标

将上述三套机制统一为通用的 **TaskManager**，提供：

1. **统一的任务生命周期管理**：创建 → 执行 → 完成/失败
2. **统一的 WS 进度推送**：所有任务类型走同一个消息格式
3. **统一的并发控制**：全局最多 5 个活跃任务，单流程最多 1 个
4. **统一的前端消费**：前端只监听一种消息类型
5. **可复用的数据模型**：DAG 流程、补数、特征计算等场景均可用

## 3. 核心数据模型

### 3.1 Task

```python
@dataclass
class Task:
    task_id: str                # "flow-" + uuid4.hex[:8]
    task_type: str              # "dag_flow" | "backfill" | "feature_compute"
    flow_id: Optional[int]      # 关联的 flow_id
    flow_name: Optional[str]
    status: str                 # pending → running → completed / failed
    progress_pct: int = 0       # 整体进度 0-100
    current_detail: str = ""    # 当前状态描述
    nodes: List["TaskNode"]     # 子节点列表
    error: Optional[str] = None
    created_at: str = ""
    started_at: Optional[str] = None
    finished_at: Optional[str] = None
```

### 3.2 TaskNode

```python
@dataclass
class TaskNode:
    node_name: str              # 节点名（如 "kline"）
    run_id: str                 # 节点级别的子 run_id
    status: str                 # pending → running → success / failed
    log_id: int                 # dag_run_log 表主键
    progress_pct: int = 0       # 节点内部进度 0-100
    rows: int = 0               # 处理行数
    detail: str = ""            # 当前状态描述
    error: Optional[str] = None
    started_at: Optional[str] = None
    finished_at: Optional[str] = None
```

### 3.3 WS 消息格式

```json
{
  "type": "task_progress",
  "task_id": "flow-a1b2c3d4",
  "task_type": "dag_flow",
  "flow_id": 5,
  "flow_name": "每日数据采集",
  "status": "running",
  "progress_pct": 60,
  "current_detail": "3/6 个节点完成",
  "nodes": [
    {"node_name": "cron",     "status": "success",  "rows": 1},
    {"node_name": "kline",    "status": "success",  "rows": 4520},
    {"node_name": "fund",     "status": "running",  "progress_pct": 45},
    {"node_name": "treemap",  "status": "pending"},
    {"node_name": "stats",    "status": "pending"}
  ]
}
```

**节点/连线状态颜色映射**：

| 状态 | 颜色 | 含义 |
|------|------|------|
| `pending` | 灰色 | 待执行（默认） |
| `running` | 蓝色 | 执行中 |
| `success` | 绿色 | 执行成功 |
| `failed` | 红色 | 执行失败 |

## 4. TaskManager 设计

### 4.1 单例 + 并发控制

```python
class TaskManager:
    _instance = None
    _lock = threading.Lock()
    _tasks: Dict[str, Task] = {}     # task_id → Task
    _ws_lock = threading.Lock()      # WS 广播锁
    MAX_CONCURRENT = 5               # 全局最大活跃任务
    _running_count: int = 0          # 当前活跃任务计数
    _flow_locks: Dict[int, bool] = {}  # flow_id 层面的锁
```

**并发规则**：
- 创建任务时检查 `_running_count >= MAX_CONCURRENT` → 拒绝 (429)
- DAG flow 任务额外检查 `_flow_locks.get(flow_id)` → 拒绝
- 任务完成时 `_running_count -= 1`，释放 flow 锁

### 4.2 状态机

```
                  ┌─────────┐
                  │ 创建任务  │
                  └────┬────┘
                       │
                       ▼
                  ┌─────────┐
                  │ pending │
                  └────┬────┘
                       │ start
                       ▼
                  ┌─────────┐
            ┌─────│ running │─────┐
            │     └─────────┘     │
            │ 全部完成    任一失败 │
            ▼                     ▼
     ┌───────────┐        ┌───────────┐
     │ completed │        │  failed   │
     └───────────┘        └───────────┘
```

### 4.3 进度计算

```
dag_flow 类型: progress_pct = (已完成节点数 / 总节点数) × 100
    单个节点: 由节点内部回调报告（通过 _report_cb 注入）
    DagNode.fn 接收 **context 中的 _task_node_progress 回调

feature_compute: progress_pct = 分片进度 (20%~70% → 映射到 0-100)
backfill: progress_pct = stocks_done / stocks_total
```

### 4.4 WS 唤醒

复用 `app/signal.py:wake_dag_broadcast()` —— 现有机制：

```python
from app.signal import wake_dag_broadcast

# TaskManager 在进度更新后调用
wake_dag_broadcast()
```

`broadcast_dag_status` 协程中增加：

```python
from app.task.manager import TaskManager
tasks = TaskManager.get_instance().get_active_tasks()
for t in tasks:
    payload = _json.dumps({"type": "task_progress", **t.to_dict()})
    for ws in _ws_clients:
        try: await ws.send_text(payload)
        except: dead.add(ws)
```

## 5. 执行流程（DAG 流程为例）

```
HTTP POST /api/dag/flows/{flow_id}/execute
  │
  ├─ 1. execute_flow()
  │      ├─ 读 dag_flows 表
  │      ├─ TaskManager.create_task("dag_flow", flow_id, nodes)
  │      │     ├─ 检查并发限制
  │      │     ├─ 创建 Task (status="running")
  │      │     ├─ 创建 TaskNode 列表
  │      │     └─ _running_count++
  │      ├─ DagExecutor 初始化
  │      └─ 后台线程启动
  │
  └─ 立即返回 {task_id, status: "started"}


后台线程:
  │
  ├─ 2. prepare_context() 生成 run_id + log_ids
  │      └─ 将 log_ids 填充到 TaskNode.log_id
  │
  ├─ 3. _execute() 逐层执行
  │      ├─ 每节点执行前: TaskNode.status = "running"
  │      ├─ 节点 fn() 内部通过 _task_node_progress 回调报告进度
  │      ├─ 每节点完成后: TaskNode.status = "success"|"failed"
  │      ├─ 每轮完成后: Task.progress_pct = done/total
  │      └─ 每次更新 → wake_dag_broadcast()
  │
  ├─ 4. 全部完成: Task.status = "completed"
  │      └─ _running_count--; 释放 flow 锁
  │
  └─ 某节点失败: Task.status = "failed"
       ├─ 等待并行节点完成
       └─ _running_count--; 释放 flow 锁
```

## 7. 后续可复用场景

| 场景 | task_type | 节点数 | 适配方式 |
|------|-----------|--------|---------|
| DAG 流程执行 | `dag_flow` | 多个（用户编排） | 现有 `execute_flow` + DagExecutor |
| 特征补数 | `feature_compute` | 1 个 | 将 `_compute_tasks` 迁移到 TaskManager |
| 历史补数 | `backfill` | 1 个 | 将 `BackfillManager` 迁移到 TaskManager |

所有场景统一走 `TaskManager` → 统一日志、统一 WS、统一前端展示。
