# 07 - 新闻资讯模块设计（原文采集 · LLM 总结 · 与雪球交叉预留）

> 版本：v1.0（2026-09-29，第 1 层原文 + 第 2 层总结上线）
> 目标：把每日盘面之外的信息面（全市场财经快讯 / 关注池个股新闻 / 研报 / 公告）**原文入库**，逐条 LLM 总结并分层重要度，供资讯页浏览、个股详情页对照。
> 姿态：**DAG 定时流程**（每 20 分钟一轮，增量自愈），不是常驻进程，也不是全市场个股新闻全覆盖。
> 关联：design/06 §D1 把「资讯新闻流」列为第二期 —— 本设计即该期；第 3 层（资讯 × 雪球交叉分析）本期只预留字段与接口。

| # | 决策 | 内容 | 理由 |
|---|---|---|---|


## 3. 数据模型（5 表 2 视图，`app/db/schema.py`）

| 表 | 用途 | 关键列 | 设计要点 |
|---|---|---|---|
| `news_item` | 原文主表 | `source`、`category`、`source_id`、`content_hash`、`published_at TIMESTAMPTZ`、`title`、`content`、`url`、`extra JSONB` | **不分区**（约 2000-4000 条/天，1.4M 行/年，比 daily_quote 小一个量级；也避开 DO 块建分区在 `$` 字符上的语句切分坑）；`UNIQUE(source, source_id)` |
| `news_stock` | 资讯 ↔ 个股多对多 | `news_id` FK CASCADE、`stock_code`、`rel`(src/match)、`confidence` | `PK(news_id, stock_code)`；`rel='src'` 是源自带股票标注，`'match'` 是关注池名称匹配 |
| `news_summary` | LLM 派生（一对一） | `summary`、`importance SMALLINT`、`topics`、**`sentiment SMALLINT`**、`model`、`prompt_ver` | `prompt_ver` 直接建列不走 ALTER；`sentiment` 是第 3 层的对接点 |
| `news_crawl_state` | 每源游标 + 健康 | `source PK`、`cursor`、`last_published_at`、`last_fetched_at`、`last_ok`、`fail_streak`、`note` | 状态页卡片的唯一数据源 |
| `news_poll_state` | 关注池轮转 + 巨潮 orgId 缓存 | `stock_code PK`、`last_fetched_at`、`fetched_count`、`fail_count`、`org_id` | 轮转键 = `last_fetched_at NULLS FIRST` |

视图：`v_focus_pool`（关注池唯一定义，供 `only_focus` 筛选与 `v_news_feed` 复用）、`v_news_feed`（`news_item LEFT JOIN news_summary`）。

### 3.1 三条容易踩空的语义

1. **幂等主键是 `(source, source_id)`**，`content_hash` **只用于跨源去重**。同源不同 `source_id` 是两份真实文档（如 3 条标题正文完全相同的公告，`announcementId` 不同即三份），用哈希去重会静默合并丢失。
2. **未总结 = NULL，不是 0**。`summary`/`importance`/`sentiment` 为 NULL 表示 LLM 尚未处理，前端显示「待总结」；`sentiment=0` 是合法的「中性」。混用会让「未总结」被当成「中性」统计。
3. **按重要度过滤时保留未总结行**（`importance >= N OR importance IS NULL`）。总结节点滞后一轮，新采集的条目等级尚不可知；严格过滤会让「刚采集完」的窗口里列表空空而库里明明有数据 —— 本库的老毛病（静默丢数据）。

## 4. 采集层 `crawler/news/`

### 4.1 源清单与端点（实测，2026-09-29）

| category | source | 端点 | 增量方式 |
|---|---|---|---|
| flash | `cls`（主） | 财联社电报（本地签名） | `last_time`=上页最旧 ctime + `refresh_type=1` → 向旧翻页 |
| flash 备 1 | `em724` | 东财全球 7×24 | **不翻页**，`pageSize=200` 取最新（覆盖约 4 小时 ≫ 20 分钟轮询） |
| flash 备 2 | `wscn` | 华尔街见闻 7×24 | `cursor` = 下一页 `attrs['next_cursor']` → 向旧翻页 |
| stock_news | `em_stock` | 东财个股新闻（JSONP） | 关注池分片轮转，表内去重 |
| report | `em_report` | 东财研报 `qType=0` 个股 / `qType=1` 行业 | 同上（个股按池，行业按天独立拉） |
| notice | `cninfo` | 巨潮公告（需 `orgId`） | 同上 |

连通性自检：`python -m crawler.news.sources`（`probe()`）。**端点死亡率是本领域主要风险**（财联社 2026-05 死过一次、2026-07 才复活），任何「端点不通」先跑探针，不要改采集逻辑。

### 4.2 东财风控与节流

实测东财风控线：5/s、单 IP 并发 ≥10、200/min → 临时封 IP。故**所有 eastmoney.com 请求必须走 `em_get()`**：串行（锁覆盖 sleep+请求全程）+ 最小间隔 1.2s + 抖动 0.3s + 连接复用，间隔由 `strategy_config.news_collect.em_min_interval` 下发。

关注池轮转：`ORDER BY last_fetched_at NULLS FIRST LIMIT focus_shard(20)` → 池子几百只时出池周期约数小时，请求速率 ~0.9 req/s，压在东财线内。

### 4.3 幂等与自愈

- 入库前两层过滤：先按 `(source, source_id)` 批量查已有键（`news_existing_keys`），再按 `content_hash` 查跨源重复（`news_hash_sources` 返回 source 集合，只有**别的**源已有该哈希才跳过）。
- 无日期窗口：快讯只按游标增量；个股类只按池轮转 + 表内去重。机器关机漏掉的轮次由下一轮自然补上（快讯 200 条/次能覆盖 4 小时）。
- 抽出的正文才写回 `content`（`fetch_article_body` 解析 `<div id="ContentBody">`）。**注意**：正文回填会改变 `content` → 哈希变化，这正是哈希不能当幂等主键的原因。

### 4.4 静默故障防御（本模块逐条踩过）

| 故障形态 | 表现 | 对策 |
|---|---|---|
| 巨潮 orgId 兜底算法失效 | `gssz0300274` 返回 0 条公告，与「该股没公告」无法区分 | **删除兜底猜测**；`org_id` 缺失直接 raise；`totalAnnouncement>0` 却解析 0 行也 raise |
| orgId 刷新顺序错误 | `refresh_orgid_map` 早于 `news_poll_state` 建行 → UPDATE 命中 0 行，静默不刷新 | `collect_once` 开头先 `ensure_poll_rows`；映射缺失（`org_id IS NULL`）即刷新 |
| 东财住宅 IP 间歇空返回 | 只回 `passportWeb` 不回文章列表 | `fetch_em_stock_news` 缺 `cmsArticleWebOld` 键即 raise；空返回记 `fail_streak` + note，**不当作「这只票没新闻」** |
| 整轮几乎全灭却报 success | 「全夜 100% 失败报 success rows=0」的历史教训 | 两节点均：子步失败率 >50% → 写 `status='failed'` |
| 时区错一天 | 巨潮毫秒时间戳按本地时区解析会偏一天 | 全模块统一 `_TZ = +08:00`，`ms_to_dt/ts_to_dt` 显式带时区 |

## 5. LLM 层

### 5.1 公共件 `scripts/llm_batch.py`

雪球打分与资讯总结共用（复制粘贴会让两条链路口径分叉）：`extract_json_array`（`raw_decode` 取最长数组，容忍 ```json 围栏）、`pick_by_ids`（按 id 回收，幻觉 id 防御）、`llm_json_batch`（重试 + 退避）、`retry_split`（折半重试）、`run_batches`（RPM 滑动窗口闸门 + 线程池）。

- **线程模型**：并发只发生在 LLM 调用；`on_ok` 固定回主线程落库（psycopg2 连接不可跨线程）。
- **RPM 闸门统计「提交」而非「成功」**——provider 限的是请求量。
- **`.replace('{items}', payload)` ≠ `.format()`** → prompt 里的花括号**不需要转义**；few-shot 里写 `{{...}}` 会被模型原样复制成非法 JSON（曾导致 40 条全废）。

### 5.2 提示词口径（`PROMPT_VER='n2'`）

一次调用同出四字段：`{s 摘要≤60字, imp 1-3, t 主题, sent 1/0/-1}`，附 7 条 few-shot 与**逐类目重要度锚点**（快讯类「行情统计/纯列表」= 1；个股研报/公告有实质信息 = 2；全市场级或个股重大 = 3）。源侧元数据（财联社 level、见闻 score、研报 org/rating、公告 type）作为提示上下文入 prompt，**不做预筛**——先观测真实数据再决定是否省调用。

排序把关注池关联的排前面：backlog 时先出有用的。

**n1 → n2（2026-09-29）**：加 id 硬约束——「原样照抄输入的 id，不得省略；输入几条输出几条，同题近重复也要各出一条、严禁合并」。改口径必升版本号，否则新旧两套标签混在一列里，第 3 层 IC 体检时分不出来。

### 5.3 实测校准结论（勿再重复调参）

- **重要度分布是类目驱动的，不是退化的**（2026-09-29 全量 199 条）：研报 92% ≥2（本就都是有实质信息的机构观点）、快讯 64% ≥2、公告 60% ≥2、个股新闻 43% ≥2。`imp=3` 极稀疏（2/199，本就该是「全市场级/个股重大」）。
- **「摘要复述标题」是类目相关的，不是模型缺陷**：行情统计/纯列表类素材的标题本身就是摘要（6000 字的成分股清单，标题即全部信息），这类正确地落在 imp=1 被默认视图隐藏。收敛方式是在展示层抑制（标题与摘要互为前缀时不重复渲染），**不再调 prompt**。
- **`sentiment` 标签有批次组成依赖**：同一批帖子换一个 batch 组合，约 1/6 的标签会翻转（雪球打分侧同款实测）。故 `prompt_ver` 直接建列——换口径能区分，且第 3 层做 IC 体检时必须把批次构成作为混杂因子考虑。
- **吞吐与成本**（glm-4-flash）：202 条待总结用时 1.8 min（8 workers / RPM 25），全量数千条/天分摊到每轮批次内不阻塞；日均成本量级为几毛钱。
- **「整批静默消失」的根因与修法**（2026-09-29 查清，值得单独记）：现象是每轮都有一整批（10 条）计入失败、日志里除了「跳过 10 条」什么都没有。根因有两层——①模型在**同股同题多份研报**这类近重复素材上会自作主张合并条目并**丢掉整个 `id` 字段**（实测返回 9 条、键只有 `s/imp/t/sent`），`pick_by_ids` 于是全部丢弃；②`_call_batch` 把「模型回了但一条没回收到」表示成空列表，而 `retry_split` 用的是 `res is not None` → **空列表被当成功收下**：不折半、不重试、不留任何日志。三层修法：`retry_split` 改判空结果为失败（折半重试，缩到单条即孤立坏条目）+ `llm_json_batch` 空数组也当失败 + 回收不全时打印「模型返回 N 条、首条长什么样」+ prompt 加 id 硬约束（n2）。实测：同一批近重复研报连续 3 次均 10/10 回收；线上被吞掉的那批 10 条在修后的一次运行里 10/10 补齐。
  > 教训泛化：**「空结果」与「无结果」是两种失败**，前者最容易被当成成功，因为它的返回值是个合法容器。凡「错了就静默丢数据」的链路，都要能回答「这批本该 N 条，实际回收几条」。

## 6. DAG 注册

- `scripts/pipeline.py`：`dag_task_news_crawl`（读 `strategy_config.news_collect`）、`dag_task_news_summary`（读 `news_summary`）；均 `_with_hb` 心跳 + 失败率 >50% 写 failed。已注册进 `NODE_FN_MAP`（**改节点函数必须重启后端**，`NODE_FN_MAP` 是进程启动快照，否则静默 no-op）。
- `app/api/dag_types.py`：`NODE_SUB_STEPS` 两条（资讯采集 3 步 / 资讯总结 3 步）。
- 种子：`dag_config` 两行 + `strategy_config` 两行 + `dag_flows`「新闻资讯」`*/20 * * * *`、published、`cron → news_crawl → news_summary`。

配置项（`strategy_config.news_collect`）：`{flash_enabled, focus_shard:20, em_min_interval:1.2, max_pages:4, report_enabled, notice_enabled, fetch_article_body, body_max_chars:6000, report_lookback_days:180, industry_report_lookback_days:7}`；`news_summary`：`{max_items:3000, min_len:20, workers:8}`。

> ⚠️ 新发布的流程会被 cron 的 24h 补跑窗口立即触发一次（雪球流程踩过），属预期。

### 6.1 运行形态的一个已知边界

进程被硬中断（重启/kill）时，在途的 `dag_run_log` 行会停留在 `pending`/`running`：数据其实已写入或由下一轮自愈，但日志行从不清尾。**后端启动清扫器已收口此问题**（app/main.py lifespan，2026-09-29）：节点都在本进程内跑，启动瞬间不可能有在途运行，故所有 `pending`/`running` 行必属于已死进程，启动时一次性标 `failed`（detail 注明「进程重启中断」；首次清扫实收 83 行，2026-08-27 起积累）。判定历史节点是否真跑过仍以数据表与 `last_fetched_at` 为准，运行日志只看清扫器收尾之后的行。

## 10. 保留策略（本期只记录，不执行）

原文 2 年 + 摘要永久。**不要自动清理**，需要时手工执行（`news_item` 按 `published_at`，`news_stock` 随 FK CASCADE）：

```sql
-- 体检：各年原文行数与占用
SELECT date_part('year', published_at) AS y, count(*), pg_size_pretty(sum(pg_column_size(content))::bigint) AS approx_raw
FROM news_item GROUP BY 1 ORDER BY 1;

-- 删除：仅删原文（保留 news_summary 与 news_stock，因 FK CASCADE 会连带 news_stock，故先确认需求）
DELETE FROM news_item WHERE published_at < now() - interval '2 years';
```

> 注意 `news_stock` 对 `news_item` 是 `ON DELETE CASCADE` → 删原文会连带删关联；若只想瘦身正文，用 `UPDATE news_item SET content=NULL WHERE ...`（列表与总结仍可用，仅详情页无全文）。

## 12. 已知风险与对策

| 风险 | 对策 |
|---|---|
| 东财住宅 IP 间歇空返回 | `fail_streak` + 空返回率上健康卡；主备切换；**不推进错误语义**（空返回不是「没新闻」） |
| 财联社签名/端点再变 | 探针先行（`python -m crawler.news.sources`）；主备三源互备；节点失败显性化 |
| 巨潮 orgId 映射失效 | `news_poll_state.org_id` 缓存 + 缺失即重拉官方 `szse_stock.json`；**不做兜底猜测** |
| LLM 大面积失败被吞 | 节点失败率 >50% 写 failed；单条失败不落库、下轮自动重试 |
| 节点改了不生效 | `NODE_FN_MAP` 是启动快照 —— 改完**必须重启后端** |
| 数据被改后训练/评估口径漂移 | 无需处理：本模块数据不进特征与模型（第 3 层评估后再议） |
