# 11 · 大盘详情页设计

> 版本：v1.0（2026-11-21，随 v3.12.0）
> 目标：给大盘/市场一个类似个股详情页的多图表详情视图——指数角度（K线/MACD/估值）+ 全市场角度（宽度/资金/两融/宏观），全部只读聚合既有 DAG 落库表，不新增采集链路。
> 口径：市场级图表全部为日频统计口径；不做任何选股/信号判断，只做观察。

## 1. 需求与设计原则

一级导航 tab「大盘」（`#/k?idx=`，key `'k'`，icon `activity`）。用户确认的两条产品决策：

- **入口形式**：一级 tab（非二级详情页），日常看盘一键可达；
- **板块范围**：指数角度固定 K线/成交额/MACD/RSI/PE·PB/换手率；全市场角度含宽度 + 资金流 + 两融 + 宏观（行业资金流趋势为顺手的现成端点复用）。

设计原则（为什么这样做）：

1. **只读聚合，不动采集**：市场级数据全部来自既有 DAG 落库表，本模块零采集逻辑——新增采集属 data 域职责，API 层越薄越好。
2. **复用优先**：指数 K 线直接打 `/api/stock/{code}/kline?type=index`（服务端已算 BOLL/RSI/MACD），情绪条直接复用 `MarketSentiment.vue` 组件，行业资金流直接打 `/api/sector_flow_history`——新写代码只覆盖真正缺失的市场级聚合。
3. **缓存御敌**：市场级聚合是百万行级 SUM/窗口函数（冷查询 3~10s），统一 TTL 缓存 + 在途去重；日频数据变化慢，缓存收益极高。
4. **图表栈约定全盘照抄个股详情页**：同一套 `chartColors(T)`/`make()` 实例复用/联动组/主题重绘/dispose 时机，维护者只需学一套。

## 2. 数据底座盘点（设计时的实测结论）

| 数据域 | 表 | 覆盖（回补后） | 关键陷阱 |
|---|---|---|---|
| 指数日K | `index_daily_quote` | 上证 1990-12-19 / 深成 1991-04 / 沪深300 2002 / 上证50·中证500·1000 2003-04 起 | **代码无后缀**（`000001`），与估值表带后缀（`000001.SH`）不一致 |
| 指数估值 | `index_valuation` | 2004-01-02 起（tushare `index_dailybasic` 接口最早即 2004） | ts_code 带后缀；macro_daily 节点只滚 40 日窗口，历史靠回补脚本 |
| 全市场资金流 | `stock_moneyflow` | 2010-01-04 起 ~4100 个交易日 | tushare 单位**万元**（本模块 ×1e4 转 元）；elg 列 2026-09 才加，但 2010 起历史行已回填，口径一致 |
| 市场宽度 | `daily_quote` + `stock_master` | 2000 起（窗口函数现算） | 表无 pct_chg/pre_close，用 `LAG(close_hfq)` 自算；ETF/转债必须 `stock_type='stock'` 过滤 |
| 两融 | `stock_margin_detail` | 2014-01-02 起 | 列名映射：`fin_amount=rzye`、`sec_amount=rqye`、`total_amount=rzrqye`，单位**元** |
| 宏观 | `macro_indicator` | CPI/PPI/M0M1M2/GDP 1990 起；SHIBOR 2006-10 起 | value 统一存同比（shibor 存隔夜利率 %）；GDP 按季度 |
| 行业资金流 | `sector_flow_daily` | ~60 日滚动 | 现成端点 `/api/sector_flow_history`，单位元 |

**核心陷阱（本模块最高频的坑）**：同一"指数"在两张表里代码格式不同——行情表裸码、估值表带后缀。`app/api/market.py` 用 `MAIN_INDEXES`（带后缀）+ `BARE` 映射（裸码）统一管理，跨表 JOIN 前必须先转换。前端 `MarketView.vue` 的 `IDXES` 数组同样双码并存（`ts`/`bare`）。

## 3. 后端 API 设计（`app/api/market.py`）

六个只读端点，`APIRouter(tags=["market"])`，在 `main.py` 以 `prefix="/api"` + JWT 依赖挂载（对齐 stock/cb/risk）：

| 端点 | 内容 | TTL | 冷查询 |
|---|---|---|---|
| `GET /market/overview` | 情绪仪表 + 7 指数行情/估值/分位 + 资金/两融/宏观快照 | 60s | 0.3s |
| `GET /market/valuation/{ts_code}?days=` | 单指数 PE/PB/换手时序 + 窗口内 30/70 分位 + 最新分位 | 600s | <0.1s |
| `GET /market/moneyflow?days=` | 全市场逐日 `Σ(特大+大单净额)`、`Σ net_mf_amt`、买卖合计 + 前端累计线 | 300s | 8~10s |
| `GET /market/breadth?days=` | 逐日涨/跌/平家数 + 涨跌停近似（±9.8%） | 300s | 3~7s |
| `GET /market/margin?days=` | 全市场逐日融资/融券/两融合计 | 300s | 0.9s |
| `GET /market/macro` | 全部宏观指标全历史时序 | 600s | <0.1s |

### 3.1 缓存与并发规范

- **模块级 TTL 缓存**：`_cached(key, ttl, fn)`，手写模式对齐 `stock.py`；key 含参数（`("valuation", ts_code, days)`）。
- **在途去重**：`threading.Event` 让并发 miss 等首个计算者，30s 超时兜底自算。冷查询秒级 + 多浏览器会话同时打开页面时，无去重会重复跑 10s 重查询——这是与 stock.py 缓存的关键差异（那边全是毫秒级查询）。
- **NaN 纪律**：所有出库数值过 `_num()`（NaN/Inf → None，JSON 序列化会炸），沿用 stock.py 的既有教训。

### 3.2 分位口径

- **overview 表**：全历史分位（SQL `percent_rank()` 开窗，`index_valuation` 仅 ~4 万行全扫很便宜）。
- **valuation 时序图**：分位在返回窗口内用 Python 算（`days=10000` 即全历史）。不用 SQL `percent_rank()` 的原因：开窗逐行返回，取"最新值的分位"别扭；Python `sorted + 计数` 直白且数据已在内存。
- **前端分位线**：PE/PB 双轴图各自画 30/70 分位 markLine，`pe_pct` ≥70% 红 / ≤30% 绿着色（侧栏表）。

### 3.3 关键 SQL 技巧：递归 CTE skip-scan

`SELECT DISTINCT trade_date FROM daily_quote ORDER BY DESC LIMIT n` 在千万行表上是全索引扫描 + 去重（5s+）。换成递归 CTE 沿索引跳跃取 distinct 值（毫秒级），全模块统一模板 `_RECENT_DATES`（5 处使用）：

```sql
WITH RECURSIVE dd AS (
    (SELECT trade_date FROM {table} ORDER BY trade_date DESC LIMIT 1)
    UNION ALL
    SELECT (SELECT trade_date FROM {table} WHERE trade_date < dd.trade_date
            ORDER BY trade_date DESC LIMIT 1)
    FROM dd WHERE dd.trade_date IS NOT NULL
)
SELECT trade_date FROM dd WHERE trade_date IS NOT NULL ORDER BY trade_date DESC LIMIT :n
```

首支括号必须包住（UNION 内 ORDER BY/LIMIT 语法要求）；末支返回 NULL 行，外层 WHERE 过滤并令递归终止。注意模板参数名固定 `:n`，外层传参必须用 `"n"`（曾因键名不匹配炸过一次）。

### 3.4 市场宽度口径

- 个股涨跌：`LAG(close_hfq) OVER (PARTITION BY stock_code ORDER BY trade_date)` 对前一**有效**收盘（停牌断档自然跳过），窗口比请求多取 1 个交易日供 LAG 用（`days+1`）。
- 涨跌停：`pct ≥ 9.8% / ≤ -9.8%` **近似口径**——10cm 主板近似准，20cm 创业板/科创板涨停算不进，ST 5% 涨停会误入。只看相对强度，别当精确涨跌停用（图注已声明）。
- 过滤：`stock_master.stock_type='stock'` 剔除 ETF/转债；`close_hfq > 0 AND prev > 0` 防零价行。

## 4. 历史回补（三脚本）

回补脚本通用规范：幂等 upsert 可重跑续传、按缺口检测跳过（`min(trade_date) <= start` 即 skip）、配额走 `TushareQuota`（余量 <20 收工）、`quota.persist(db)` 收尾持久化、**多脚本必须串行跑**（限流是进程内的，多进程并行会超 tushare 限流且配额计数互相覆盖）。

| 脚本 | 内容 | 实测消耗 |
|---|---|---|
| `scripts/backfill_index_valuation.py` | `index_dailybasic` 按 ts_code × 8 年分块，7 指数铺满 2004→今 | 32,708 行 / 21 次调用 |
| `scripts/backfill_index_kline.py` | `index_daily` 按 ts_code 区间直查，复用 `batch_upsert_index_kline`（vol×100、amount×1000 换算沿用 `fetch_index_kline` 口径） | 上证 1990 起 8768 行 / 15 次 |
| `scripts/backfill_macro.py` | 月度/季度一次拉全历史（cpi=nt_yoy、ppi=ppi_yoy、m 系=各 yoy、gdp=gdp_yoy，extra 保留原始字段，口径对齐 macro_daily 节点）；`--shibor` 按日循环补 2006-10 起（接口只有单日参数，`shibor_quote` 区间接口是银行报价语义不能替代定盘利率） | 1434 行 / 4 次 + SHIBOR ~5200 次后台 |

**探测先行**：写回补脚本前先试调接口确认最早可用日期（各接口不同：K线 1990、估值 2004、CPI 1990、SHIBOR 2006-10），不要假设起点。

**两个血泪教训**：

1. **extra JSONB 列不能带 NaN**：`json.dumps(float('nan'))` 输出裸 `NaN` 字面量，PostgreSQL jsonb 直接拒收（早期宏观数据常见 NaN）。value 列有 `fv()` 守卫而 extra 漏了 → 加 `san()` 递归清洗。
2. **库内代码格式不统一是常态**：tushare `stk_code` 带后缀（v3.11 已踩过）、`index_daily_quote.index_code` 裸码、`index_valuation.ts_code` 带后缀——入库前必须核对目标列的既有格式。

## 5. 前端设计（`MarketView.vue`）

### 5.1 路由注册（新增 tab 的标准三件套）

1. `stores/nav.js`：新增 `midx` ref（选中指数）；`parseHash` 加 `path === '/k'` 分支（读 `?idx=`）；`syncHash` 加 `case 'k'`（默认指数不带参数、其余 `?idx=xxx` 可分享）；fallback map 加 `'/k':'k'`；`watch(midx)` 同步 URL。
2. `App.vue`：`primaryTabs` 注册（`{key:'k', label:'大盘', icon:'activity'}`）+ 内容区 `v-if` 挂载 + `pageMeta`/`titleMap` 标题。
3. 组件不接收 props，选中态全走 nav store（与 DetailView 的 props 模式不同——一级 tab 无"来路"概念）。

### 5.2 图表栈组织（对齐 Detail.vue 约定）

- **联动组**（`echarts.connect('mk')`）：K线/成交额/MACD/RSI 四图共用同一 xAxis 日期数组 + dataZoom，滚轮缩放全组同步。**关键：`echarts.connect(group)` 只连声明了 `chart.group` 的实例**——必须逐个 `c.group = 'mk'`，漏了 connect 空转（Detail.vue 的 `c.group='s'` 同款）。
- **独立组**：PE·PB/换手/宽度/资金流/两融/行业流各自日期域不进联动组（照 Detail.vue 的 PE 图处理）。
- **实例管理**：`make(id, opt)` 复用 `el._echart`；`onBeforeUnmount` dispose（onUnmounted 时 DOM 已查不到）；resize 挂 window + onUnmounted 移除；`watch(theme.isDark)` 全量重绘（`chartColors` Proxy 每次取值读当前主题，重绘即换肤）。
- **数据留存**：所有图表数据存 ref，主题切换重绘时从 ref 重画而非重新请求。
- **竞态**：模块级 `loadSeq`，切指数/切区间均 `++loadSeq` 使在途请求失效（切区间忘记递增曾引入渲染竞态，审查已修）。
- **图标**：只用 `utils/icons.js` 注册表里的名字（如 `activity/candlestick/percent/zap/target/shield/shuffle/calendar/download`），未注册名渲染为空白不报错——写模板时对照清单。

### 5.3 页面结构

```
顶栏：7 指数 chips + 11 档区间（1月~20年/全部=10000 交易日）
MarketSentiment 情绪条（复用组件，60s 自轮询）
├─ 左列（联动组）：K线+MA+BOLL / 成交额 / MACD / RSI
│   左列（独立组）：PE·PB+分位线 / 换手率 / 市场宽度 / 资金流(柱+累计线)
│                  两融余额 / 行业资金流累计(Top8)
└─ 右侧栏 330px sticky：指数估值对比表（点行切主图）/ 全市场快照 / 宏观指标卡
```

区间档位语义：交易日数（1年=250）；「全部」=10000 覆盖 1990 起全量。长档位 K 线 8700+ 根 candlestick，ECharts dataZoom 下无性能问题。

## 6. 已知限制与后续优化

| 项 | 现状 | 后续 |
|---|---|---|
| moneyflow/breadth 冷查询 8~10s | 瓶颈在主聚合（~900 万行 SUM / ~275 万行 LAG），skip-scan 只消掉 DISTINCT 部分；TTL 300s + 在途去重已兜底 | 正解是 DAG 物化表（每日增量 SUM 落 `data_stats_cache` 或专表），需动 `pipeline.py`（高冲突文件，单独排期） |
| 估值窗口分位 vs 全历史分位 | valuation 端点分位按请求窗口算（`days=10000` 即全历史）；overview 侧栏恒为全历史 | 前端估值图固定请求 10000，两处口径已一致 |
| 涨跌停近似口径 | ±9.8% 阈值混杂 10cm/20cm/ST | 需精确时按板块涨停价规则重写（股票代码段判断） |
| SHIBOR 深历史 | 后台长跑（~5200 次调用，2006-10 起），接口仅单日参数 | 无区间接口，等幂等长跑自然完成 |
| 科创50/中证2000/北证50 | K 线表无数据（`index_daily` 按交易日全市场拉不到这三个） | 需按 ts_code 补（backfill_index_kline.py 直接支持 `--codes`） |
| 海外指数 | 无数据源 | 不在本模块范围 |

## 7. 规范摘要（本模块约定）

财经博主常展示的"恐慌指数"两类：VIX 式隐含波动率（A股官方 iVIX 2018 已停发、tushare 无现成接口、自算需期权全量数据 2015 起）与复合情绪分。本模块走**自建情绪分序列**路线——数据条件齐全（2000 起宽度/涨跌停/中位数全可从 daily_quote 重算），历史比博主展示更长。

### 8.1 口径决策（最重要的一条）

实时情绪分含 VWAP 成分（20 分，盘中实时概念），**历史无法回补**。若每日增量用完整实时公式、历史用降级公式，序列会出现系统性跳变，趋势图就废了。因此：

| 列 | 口径 | 谁写入 |
|---|---|---|
| `score` | **三成分口径**：up_ratio×40 + (median+2)/4×20 + 涨跌停平衡×20 + VWAP 项恒按 `_verdict` 缺省 **10 分**（与公式对缺数据的 fallback 一致） | 历史回补 + 当日 DAG 节点（同一公式） |
| `score_rt` | 实时四成分分（含 VWAP），仅当日节点落库有值 | 仅 `sentiment_daily` DAG 节点 |
| `vwap_ratio` | 指数站上 VWAP 占比（历史 NULL） | 仅当日节点 |

判级/评分复用 `market_sentiment._verdict`（传入 above_count=0, index_count=0），**公式单点维护**——改实时公式时历史口径自动跟随，序列不会与实时仪表分叉。

### 8.2 数据流

- **表**：`market_sentiment_daily`（PK trade_date），DDL 在 schema.py（CREATE_INDEX_VALUATION 区块后），ALL_TABLES 尾部注册
- **当日增量**：DAG 节点 `sentiment_daily`（pipeline.py，NODE_FN_MAP 注册），独立流程「市场情绪日度」`30 15 * * *` 收盘后触发（等 treemap 快照落定、避开 17:00 主流程）；当日无快照（周末）跳过；流程播种照雪球风格（init_db `WHERE NOT EXISTS`），cron_scheduler 纯表驱动零代码
- **历史回补**：`scripts/backfill_sentiment_daily.py`——从 daily_quote 重算（递归 CTE 取交易日窗口 + `LAG(close_hfq)` + `percentile_cont(0.5)` 中位数 + 涨跌停阈值按代码段 CASE），分块 250 交易日（每块带前一交易日供 LAG 边界），判级直接 import `_verdict`；纯库内重算不耗配额
- **API**：`GET /api/market/sentiment-history?days=`（TTL 300s）
- **前端**：大盘页左列卡片「市场恐慌指数趋势」——score 折线 `visualMap` 按值分档着色（<25 跌色 / 25-45 警色 / 45-70 中性 / ≥70 涨色，单值数据 dimension=0）+ 25/45/70 分档参考线

### 8.3 实测与已知近似

- 历史关键日验证：2007-05-30 印花税暴跌 12.3 分 panic（跌停 876）、2020-02-03 疫情开盘 12.3 panic（跌停 2438）、2024-09-30 九二四行情 89.9 strong（99.7% 上涨）——与真实历史吻合
- **已知近似**：①历史涨跌用 hfq 对 LAG 前收（除权日是真实收益口径，与腾讯官方前收在除权日有细微差异，对中位数/涨跌停计数可忽略）；②涨跌停 ±9.8/19.8 按代码段近似（ST 5% 误入、20cm 极端日部分计入），与实时 `_limit_pct` 一致；③当日节点分与回补分可能有 ~0.4 分微差（快照收盘时点成分 vs hfq 重算，如 2026-11-20 节点 17.7 vs 回补 17.3），同为 panic 档不影响趋势判读；④2015-08-24 类"极端对冲日"（涨停 1184/跌停 817 同现）涨跌停平衡项会把分拉回中性，公式对双向极端不敏感——看趋势时结合宽度图交叉验证



1. 新增市场级端点一律：只读聚合 + `_cached` TTL + `_num()` 出库 + `try/finally db.close()`；不写采集逻辑。
2. 跨表引用指数代码必须过 `MAIN_INDEXES`/`BARE` 映射，禁止裸字符串拼。
3. 资金流单位：`stock_moneyflow` 万元（×1e4），`stock_margin_detail` 元——新端点出库一律转元，前端再格式化亿。
4. 千万行表取"最近 N 个 distinct 日期"用 `_RECENT_DATES` 模板，禁止 `SELECT DISTINCT ... LIMIT`。
5. 回补脚本：幂等 + 缺口检测 + 配额护栏 + 串行执行 + 探测先行；完成后 `quota.persist(db)`。
6. 前端新图表进联动组前先 `chart.group = 'mk'`；切参数必递增 `loadSeq`。

## 8. 市场恐慌指数趋势（v3.13 增补）

| 列 | 口径 | 谁写入 |
|---|---|---|
| `score` | **三成分口径**：up_ratio×40 + (median+2)/4×20 + 涨跌停平衡×20 + VWAP 项恒按 `_verdict` 缺省 **10 分**（与公式对缺数据的 fallback 一致） | 历史回补 + 当日 DAG 节点（同一公式） |
| `score_rt` | 实时四成分分（含 VWAP），仅当日节点落库有值 | 仅 `sentiment_daily` DAG 节点 |
| `vwap_ratio` | 指数站上 VWAP 占比（历史 NULL） | 仅当日节点 |

判级/评分复用 `market_sentiment._verdict`（传入 above_count=0, index_count=0），**公式单点维护**——改实时公式时历史口径自动跟随，序列不会与实时仪表分叉。

### 8.2 数据流

- **表**：`market_sentiment_daily`（PK trade_date），DDL 在 schema.py（CREATE_INDEX_VALUATION 区块后），ALL_TABLES 尾部注册
- **当日增量**：DAG 节点 `sentiment_daily`（pipeline.py，NODE_FN_MAP 注册），独立流程「市场情绪日度」`30 15 * * *` 收盘后触发（等 treemap 快照落定、避开 17:00 主流程）；当日无快照（周末）跳过；流程播种照雪球风格（init_db `WHERE NOT EXISTS`），cron_scheduler 纯表驱动零代码
- **历史回补**：`scripts/backfill_sentiment_daily.py`——从 daily_quote 重算（递归 CTE 取交易日窗口 + `LAG(close_hfq)` + `percentile_cont(0.5)` 中位数 + 涨跌停阈值按代码段 CASE），分块 250 交易日（每块带前一交易日供 LAG 边界），判级直接 import `_verdict`；纯库内重算不耗配额
- **API**：`GET /api/market/sentiment-history?days=`（TTL 300s）
- **前端**：大盘页左列卡片「市场恐慌指数趋势」——score 折线 `visualMap` 按值分档着色（<25 跌色 / 25-45 警色 / 45-70 中性 / ≥70 涨色，单值数据 dimension=0）+ 25/45/70 分档参考线

### 8.3 实测与已知近似

- 历史关键日验证：2007-05-30 印花税暴跌 12.3 分 panic（跌停 876）、2020-02-03 疫情开盘 12.3 panic（跌停 2438）、2024-09-30 九二四行情 89.9 strong（99.7% 上涨）——与真实历史吻合
- **已知近似**：①历史涨跌用 hfq 对 LAG 前收（除权日是真实收益口径，与腾讯官方前收在除权日有细微差异，对中位数/涨跌停计数可忽略）；②涨跌停 ±9.8/19.8 按代码段近似（ST 5% 误入、20cm 极端日部分计入），与实时 `_limit_pct` 一致；③当日节点分与回补分可能有 ~0.4 分微差（快照收盘时点成分 vs hfq 重算，如 2026-11-20 节点 17.7 vs 回补 17.3），同为 panic 档不影响趋势判读；④2015-08-24 类"极端对冲日"（涨停 1184/跌停 817 同现）涨跌停平衡项会把分拉回中性，公式对双向极端不敏感——看趋势时结合宽度图交叉验证
