# 12 — 开发分支、工作树与测试环境规范

> 版本：v1.0（2026-11-23）
> 目标：主仓库永远停在 `main`；每个任务独立分支/工作树/端口/测试库；合并后立即回收，避免"新会话跑到旧分支、旧测试库"。

---

## 1. 核心原则

1. **主仓库只放 `main`**：`/home/bnbnyu/projects/stone` 永远 checkout `main`，用于 3000/8000 验收环境；禁止在主仓库切换功能分支。
2. **一任务一分支一工作树**：每个开发任务从最新 `main` 建独立分支，并放在独立 worktree；任务结束即合并、删除。
3. **一任务一端口对**：主环境固定 `8000/3000`；任务环境从 `8100/3100` 起顺延。
4. **一任务一测试库（仅 schema/迁移类任务）**：默认共享 `stone_test`；需要改表/迁移时，从 `stone_test` 克隆 `stone_t_<slug>`，任务结束删除。
5. **不跨任务复用**：旧分支、旧 worktree、旧测试库不得直接给新任务继续用；只能作为参考（只读）或先合并/删除。
6. **`main` 只接受合并**：功能分支必须测试通过、验收后合并；`main` 始终保持可运行、可构建、测试通过。

---

## 2. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 分支 | `<type>/<slug>`；slug 小写短横线，2–4 个词 | `feat/cb-strategy`, `fix/ws-auth`, `docs/rbac-rule` |
| 工作树 | `/home/bnbnyu/projects/stone-worktrees/<slug>` | `/home/bnbnyu/projects/stone-worktrees/cb-strategy` |
| 测试库 | schema 任务：`stone_t_<slug>`；其他：`stone_test` | `stone_t_cb_strategy` |
| 后端端口 | 主环境 8000；任务 8100 + slot | 8100, 8101, 8102 |
| 前端端口 | 主环境 3000；任务 3100 + slot | 3100, 3101, 3102 |

> slug 使用下划线替换连字符用于数据库名（PostgreSQL 标识符不允许 `-`，除非加引号）。

## 3. 标准任务流程

### 3.1 开工

```bash
cd /home/bnbnyu/projects/stone
git fetch --prune
git switch main
git pull --ff-only
git status --short          # 必须干净
git worktree list
```

创建任务工作树：

```bash
git worktree add -b feat/<slug> \
  /home/bnbnyu/projects/stone-worktrees/<slug> main
cd /home/bnbnyu/projects/stone-worktrees/<slug>
cp /home/bnbnyu/projects/stone/.env .env
```

分配端口（从下表取第一个空闲）：

| slot | 后端 | 前端 | 测试库 |
|---|---|---|---|
| 0（主） | 8000 | 3000 | `stock_monitor`（生产验收） |
| 1 | 8100 | 3100 | `stone_test` / `stone_t_<slug>` |
| 2 | 8101 | 3101 | 同上 |
| 3 | 8102 | 3102 | 同上 |
| 4 | 8103 | 3103 | 同上 |

启动后端时显式传端口并写入 PID：

```bash
nohup venv/bin/python -m uvicorn app.main:app \
  --host 127.0.0.1 --port 8100 > .dev/backend.log 2>&1 &
echo $! > .dev/backend.pid
```

前端 Vite 通过环境变量指定端口与代理目标（需 `vite.config.js` 支持）：

```bash
VITE_PORT=3100 VITE_API_TARGET=http://127.0.0.1:8100 npm run dev
```

### 3.2 测试库

- 非 schema 任务：直接使用共享 `stone_test`（与 `stock_monitor` 隔离）。
- 历史库 `stock_monitor_mu_test` 落地本规范时重命名为 `stone_test`（先停 8100 连接，再 `ALTER DATABASE ... RENAME TO stone_test`）。
- 涉及 `app/db/schema.py`、`init_db` 迁移、主键/视图变更：
  ```sql
  CREATE DATABASE stone_t_<slug> TEMPLATE stone_test;
  ```
  工作树 `.env` 的 `DATABASE_URL` / `DATABASE_URL_SYNC` 指向 `stone_t_<slug>`。
- 禁止自动化测试连接生产库 `stock_monitor`；生产库只用于 3000/8000 人工验收。
- 迁移类任务必须：
  1. 在任务库跑一遍 `init_db`；
  2. 跑验证 SQL/隔离测试；
  3. 备份生产受影响表后再对生产库迁移；
  4. 迁移失败立即回滚并保留日志。

### 3.3 收尾

```bash
# 1. 测试与构建
pytest tests/unit tests/integration -q
npm --prefix web-v2 run build

# 2. 合并
cd /home/bnbnyu/projects/stone
git switch main
git merge --no-ff feat/<slug>

# 3. 回收
git worktree remove --force /home/bnbnyu/projects/stone-worktrees/<slug>
git branch -d feat/<slug>
dropdb stone_t_<slug>          # schema 任务
```

任务分支生命周期建议 **≤ 3 天**；超过 3 天仍未合并，必须合并、拆分或明确废弃。

## 4. 会话开工/收尾检查清单

### 开工

- [ ] 主仓库在 `main` 且工作区干净
- [ ] `git worktree list` 无同名/同任务残留
- [ ] 新分支从最新 `main` 创建，不复用旧分支
- [ ] 端口对未被占用（8100/3100 起顺延）
- [ ] schema 任务有独立 `stone_t_<slug>`；非 schema 任务明确用 `stone_test`
- [ ] 启动前记录 PID/日志路径到任务工作树 `.dev/`

### 收尾

- [ ] 单元/集成测试通过，前端构建通过
- [ ] 已合并到 `main` 并验收
- [ ] worktree 已删除、分支已删除
- [ ] 任务测试库已 drop（共享 `stone_test` 保留）
- [ ] 后台进程已停止，端口已释放
- [ ] 未把测试账号/临时数据留在生产库

## 5. 分支清理策略

- 所有已合并到 `main` 的本地分支应删除；远程分支用 `git fetch --prune` 同步。
- 每周至少清理一次：
  ```bash
  git branch --merged main | grep -v '^\*' | xargs -r git branch -d
  git worktree prune
  ```
- 未合并分支超过 7 天：先确认是否有未提交价值，再合并或删除；禁止无限期堆积。
- 长期实验（模型/回测）也走同一流程，不单独维护"永久实验分支"。

---

## 6. 与权限节点规范的关系

新功能分支开始前，按 `design/10` §20 判定功能节点；若新增/调整权限节点，必须在同一分支内完成：

- `app/auth/definitions.py`
- `app/auth/route_permissions.py`
- 角色默认矩阵/迁移种子
- 前端导航/`v-perm`
- `design/10` 节点表与测试矩阵
- 至少一条"有权通过 + 无权隐藏/403"测试

---

## 7. 例外

- **紧急 hotfix**：从 `main` 建 `fix/<slug>`，同样使用独立 worktree/端口；修复后立即合并，不直接在 `main` 改。
- **纯文档/配置**：可用 `docs/<slug>` / `chore/<slug>`，仍走 worktree；不需要测试库。
- **多会话并行**：每个会话只操作自己的 worktree；禁止进入他人 worktree、禁止 kill 他人端口进程。

---

## 8. 环境状态检查脚本

每次开工前运行：

```bash
venv/bin/python scripts/dev_status.py
```

输出：

- 当前仓库 branch / 工作区是否干净
- 所有 worktree（发现旧任务残留）
- merged / unmerged 分支数量与未合并分支列表
- 3000/8000/8100–8104 端口占用
- `stone*` / `stock_monitor*` 数据库与大小

原则：**状态脚本不替开发者做删除**；确认旧任务已合并后，再手工 `git worktree remove` / `git branch -d` / `dropdb`。
