# K道量化平台 - 特征管理模块开发设计方案（完整版）
## Feature Management Module - Development Design Specification v2.0

---

## 一、模块概述

### 1.1 模块定位

特征管理模块是 KEPL 语言体系的 **“逻辑组装层”**。它负责将**函数管理模块**提供的原子算子（如 `ma`、`rsi`）与**数据源实体**（`stock`、`etf`、`global`）绑定，通过 KEPL 公式表达式，定义出具体的特征（如“5日均线偏离度”），并对这些特征的元数据、依赖关系、版本状态、数据质量进行全生命周期管理。

> **边界声明**：本模块**只负责特征的“定义”、“元数据管理”和“数据质量监控”**。特征的“周期性计算调度”与“物理数据写入”由独立的 **DAG 调度模块** 负责。本模块为 DAG 提供特征列表、依赖图谱、计算优先级等基础数据支撑。

### 1.2 核心目标

1. 提供特征的可视化注册、编辑、列表与详情查询界面。
2. 建立特征间的依赖关系网（基础特征 → 复合特征），自动检测循环依赖。
3. 管理特征的状态（草稿/已启用/待重算/已弃用），支持级联状态标记。
4. **基于“完整时空矩阵”理念，监控特征的数据质量（数据完整度、待计算格子数、新鲜度）**。
5. 为 DAG 调度模块提供完整的特征元数据导出接口（含拓扑关系）。

### 1.3 设计原则（贯穿全文）

- **单一职责**：特征管理只定义“算什么”，不负责“何时算”和“怎么存”。
- **依赖显式化**：特征的上下游依赖关系由系统自动提取，并在UI中可视化呈现。
- **质量可观测**：每个特征的数据完整度、缺失归因、新鲜度一目了然。
- **状态联动**：上游变更自动触发下游“待重算”标记，保证数据一致性。

## 二、UI 交互设计（前端界面）

### 2.1 特征列表页（一级页面）

**路由**：`/features/list`

| UI 区域 | 内容说明 |
| :--- | :--- |
| **顶部操作栏** | 左侧标题“特征管理（Feature Registry）”；右侧 **[+ 新增特征]** 按钮 |
| **筛选工具栏** | • 下拉筛选：`目标实体（全部/个股/ETF/指数/全局）`<br>• 下拉筛选：`状态（全部/草稿/已启用/待重算/已弃用/数据异常）`<br>• 搜索框：按“特征英文名/中文名”模糊搜索 |
| **数据表格** | 列依次为：<br>1. `特征英文名`（可点击进入详情）<br>2. `中文名`<br>3. `目标实体`（标签：个股/ETF/指数/全局）<br>4. `状态`（彩色圆点 + 文字）<br>5. **📊 数据完整度**（进度条 + 百分比，悬停显示详细统计）<br>6. **⏳ 待计算格子数**（数字，显示还有多少格子未计算）<br>7. **📅 最近计算日**（日期，若超过5个交易日未更新则标黄）<br>8. `依赖项数量`<br>9. `操作（编辑/详情/启用/停用）` |
| **分页组件** | 支持每页 10/20/50 条切换 |

**状态颜色规范**：
- 🟡 **草稿（Draft）**：刚创建，尚未正式启用。
- 🟢 **已启用（Enabled）**：正常使用中，DAG 将自动计算。
- 🔵 **待重算（Pending Recalc）**：依赖的特征发生变化，数据已过期，需重新计算。
- 🔴 **已弃用（Deprecated）**：逻辑废弃，DAG 自动跳过。
- 🟠 **数据异常（Data Anomaly）**：数据完整度低于阈值或新鲜度异常，需人工介入。

**“数据完整度”悬停气泡内容**：
```
有效格子总数：  5,000,000
已计算格子：    4,800,000 (96.0%)
待计算格子：      160,000 (3.2%)
不适用格子：       40,000 (0.8%)  ← 上市前/退市后/停牌
```

### 2.2 新增/编辑特征弹窗（核心交互）

**触发方式**：点击列表页 **[+ 新增特征]** 或某一行 **“编辑”** 按钮。

#### 2.2.1 弹窗布局（从上到下四个区域）

| 区域名称 | 字段标签 | 组件类型 | 是否必填 | 说明/校验规则 |
| :--- | :--- | :--- | :--- | :--- |
| **区域一：基础信息** | 特征英文名 | 单行文本框 | ✅ | 正则：`^[a-z][a-z0-9_]{1,63}$`。不可与已有特征重名，不可与系统保留字段（如 `close`、`volume` 等）重名。 |
| | 特征中文名 | 单行文本框 | ✅ | 最多 30 个中文字符 |
| | 目标实体 | 下拉选择框 | ✅ | 选项：`个股（stock）` / `ETF（etf）` / `指数（index）` / `全局（global）`。**选定后不可修改**。 |
| | 功能描述 | 多行文本框 | ❌ | 描述该特征的计算逻辑与业务含义 |
| **区域二：公式编辑** | KEPL 公式 | 代码编辑器（集成语法高亮 + 自动补全） | ✅ | 用户编写表达式。编辑器支持：<br>• 输入 `ma_` 自动提示已注册的函数<br>• 输入 `close` 自动识别为主实体字段<br>• 实时语法错误波浪线提示 |
| **区域三：依赖预览（只读）** | 依赖特征列表 | 标签展示区 | — | 系统根据公式自动解析：<br>• 依赖原始字段 → 显示为 `📄 close`<br>• 依赖已有特征 → 显示为 `🔗 ma_5`<br>• 若提示“将新建特征，将自动生成依赖图谱” |
| **区域四：启用设置** | 创建后直接启用 | 开关按钮 | — | 开启 = 保存后即 `enabled`；关闭 = 保存为 `draft` |
| **底部操作栏** | 按钮组 | — | — | **[验证公式]** → 仅校验语法与依赖，不保存；**[存为草稿]** → 基础校验后保存；**[保存并启用]** → 全量校验通过后保存；**[取消]** |

#### 2.2.2 “验证公式”的返回结果

点击「验证公式」后，弹窗展示以下信息：

| 验证项 | 展示内容 |
| :--- | :--- |
| ✅ 语法正确性 | 通过 / 报错（显示具体行号和错误描述） |
| ✅ 依赖提取结果 | 列出所有被引用的原始字段和已有特征 |
| ✅ 循环依赖检测 | 通过 / 若存在环，显示环路径（如 `A → B → C → A`） |
| ✅ 实体一致性 | 检查是否有跨实体不匹配的引用 |

### 2.3 特征详情页（二级页面）

**路由**：`/features/:id/detail`

#### 2.3.1 顶部信息卡

| 信息模块 | 内容说明 |
| :--- | :--- |
| **身份信息** | 特征英文名、中文名、目标实体（大号标签）、当前状态（彩色横幅） |
| **时间信息** | 创建时间、最近修改时间、最近计算日 |
| **数据质量仪表盘** | 四张微型卡片：<br>• 📊 **数据完整度**：大号百分比 + 进度条<br>• 📋 **有效格子总数**：XX,XXX,XXX 个<br>• ⏳ **待计算格子数**：XXX 个（若 > 0，显示“进行中”标识）<br>• 🚫 **不适用格子数**：XXX 个（上市前/退市后/停牌，灰色显示） |

#### 2.3.2 依赖关系图（缩略版）

以树形结构或力导向图展示：
- **上游依赖（该特征依赖谁）**：用绿色箭头从上游指向本特征。
- **下游引用（谁依赖该特征）**：用橙色箭头从本特征指向下游。

鼠标悬停时高亮显示路径，点击节点可跳转至对应特征的详情页。

#### 2.3.3 数据缺失诊断面板（折叠展开）

**视图一：二维缺失热力图（缩略版）**
- 横轴：最近 120 个交易日。
- 纵轴：缺失率最高的前 50 只股票（按缺失率降序排列）。
- 色块：🟩 有值 / 🟥 缺失 / ⬜ 不适用（上市前/退市后/停牌）。
- 点击色块区域，下方展示该日或该股的详细缺失数据。

**视图二：缺失归因饼图**
- 总缺失中，停牌导致的占比 vs 非停牌异常缺失占比。
- 若异常缺失占比 > 50%，显示红色警告：“大部分缺失非停牌导致，请检查计算逻辑或数据源。”

#### 2.3.4 数据预览（分页加载）

展示该特征在宽表中的实际数值，按日期降序排列。
- **强制分页加载**（默认每页 50 条）。
- **必须按实体代码筛选**（如输入股票代码 `000001` 查看该股的历史值）。
- 若特征实体为 `global`，则无股票代码筛选框，直接展示每日数值。
- 表格中，`NULL` 值显示为灰色 `-`，并带有悬浮提示：“该日无数据（停牌/上市前/计算失败）”。

### 2.4 特征依赖关系图（全屏弹窗）

**触发方式**：在列表页或详情页点击 **[查看完整依赖图]**。

- 前端根据后端返回的全量邻接表，使用 D3.js 或 ECharts 渲染**有向无环图（DAG）**。
- 节点颜色按“层级”区分：
  - 🟤 原始字段（`close`、`volume`）—— 灰色
  - 🔵 基础特征（`ma_5`、`rsi`）—— 蓝色
  - 🟠 复合特征（`bias_5d`）—— 橙色
  - 🔴 顶层策略特征（`alpha_factor`）—— 红色
- 鼠标悬停时高亮上下游路径，点击节点跳转至对应特征详情页。
- 支持导出为图片（PNG/SVG）。

## 三、数据库存储设计

### 3.1 主表：`features`

| 字段名 | 字段类型 | 约束/默认值 | 对应 UI 字段 | 详细说明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | BIGINT | PRIMARY KEY, AUTO_INCREMENT | — | 主键自增 ID |
| `feature_name` | VARCHAR(64) | UNIQUE, NOT NULL | 特征英文名 | 唯一索引，在公式中被引用时使用 |
| `display_name` | VARCHAR(64) | NOT NULL | 特征中文名 | 前端展示用 |
| `target_entity` | VARCHAR(16) | NOT NULL | 目标实体 | 枚举：`stock` / `etf` / `index` / `global` |
| `description` | TEXT | — | 功能描述 | 特征业务含义说明 |
| `formula` | TEXT | NOT NULL | KEPL 公式 | 存储完整的 KEPL 表达式源码 |
| `depends_on` | JSON | DEFAULT '[]' | 依赖预览（自动提取） | 存储该特征直接依赖的**原始字段名**和**特征名**数组。<br>示例：`["close", "ma_5"]` |
| `status` | VARCHAR(16) | DEFAULT 'draft' | 启用状态 | 枚举：`draft` / `enabled` / `pending_recalc` / `deprecated` / `data_anomaly` |
| **数据质量统计字段（由 DAG 回写）** | | | | |
| `total_effective_cells` | BIGINT | DEFAULT 0 | — | 该特征当前累计的“有效格子”总数（即分母） |
| `missing_cells_total` | BIGINT | DEFAULT 0 | — | 该特征当前累计的缺失格子总数（即分子） |
| `pending_cells_total` | BIGINT | DEFAULT 0 | — | 当前 `_calc_status = 'PENDING'` 的格子数量 |
| `data_completeness` | DECIMAL(5,4) | DEFAULT 0 | 数据完整度 | `1 - missing_cells_total / total_effective_cells` |
| `latest_computed_date` | DATE | NULL | 最近计算日 | DAG 最后一次成功计算该特征的日期 |
| `data_anomaly_reason` | VARCHAR(128) | NULL | — | 当 `status='data_anomaly'` 时，记录具体原因（如“完整度低于80%”或“连续5日未更新”） |
| **审计字段** | | | | |
| `created_by` | VARCHAR(64) | — | — | 创建人（后期扩展） |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | — | 创建时间 |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | — | 更新时间 |

> **关于 `depends_on` 使用 JSON 的说明**：特征依赖数量通常不超过 10~20 个，JSON 查询性能足够。独立建依赖表会增加查询复杂度，且由于不存在“多级嵌套”的聚合查询需求，JSON 是性价比最高的方案。

### 3.2 辅助表：`feature_data_log`（审计与操作日志）

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | BIGINT | 主键 |
| `feature_id` | BIGINT | 外键关联 `features.id` |
| `action` | VARCHAR(16) | `create` / `update` / `recalc` / `mark_pending` / `deprecate` / `anomaly_detected` |
| `change_summary` | TEXT | 变更摘要（如“公式从 A 修改为 B”） |
| `triggered_by` | VARCHAR(64) | 触发者（用户 / 系统自动） |
| `created_at` | DATETIME | 操作时间 |

## 四、核心校验与业务规则

### 4.1 新增/编辑时的校验（前后端协同）

| 校验项 | 触发时机 | 实现层级 | 失败提示 |
| :--- | :--- | :--- | :--- |
| 特征英文名格式 | 输入框失焦 | 前端正则 | “英文名必须是小写字母开头，仅包含小写字母、数字、下划线。” |
| 特征英文名唯一性 | 提交时 | 后端查库 | “特征英文名 ‘xxx’ 已被占用，请修改。” |
| 目标实体不可变 | 编辑时 | 前端置灰 + 后端校验 | “已创建的特征不可变更目标实体，请新建特征。” |
| **KEPL 公式语法校验** | 点击「验证公式」或保存时 | 后端调用公式解析器 | 返回具体的语法错误位置及描述（参考 KEPL 错误规范规范）。 |
| **依赖项存在性校验** | 保存时 | 后端解析 + 查库 | 扫描公式中出现的所有“已存在特征名”，若某个名称既不是原始字段、也不是已注册特征，报错：“公式中引用的 ‘xxx’ 不是有效的字段或特征名称。” |
| **循环依赖检测** | 保存时（仅 `enabled` 状态强制检测） | 后端拓扑排序 | 若检测到环，报错：“检测到循环依赖：特征 A 与 B 互相引用，请解除后重试。” |
| **实体一致性校验** | 保存时 | 后端逻辑 | 若当前特征实体是 `stock`，而公式中引用了另一个实体为 `etf` 的特征，且未通过 `global` 或中括号广播，则报错：“实体不匹配：`stock` 实体不能直接引用 `etf` 实体的特征。” |
| 状态流转合法性 | 用户切换状态时 | 前端 + 后端 | • 若存在下游特征依赖本特征，**不允许**直接将状态从 `enabled` 切换为 `deprecated`。<br>• 若本特征处于 `pending_recalc`，下游特征需同步标记。 |

### 4.2 循环依赖检测算法（后端核心逻辑）

当用户保存特征时，后端执行以下步骤：

1. **提取本特征直接依赖**：通过公式解析器，扫描出 `depends_on` 数组。
2. **构建全局依赖图**：从数据库加载所有 `status != 'deprecated'` 的特征，连同本次新增/修改的特征，构建一张有向图（边：`依赖者 → 被依赖者`）。
3. **拓扑排序（Kahn 算法）**：
   - 统计每个节点的入度。
   - 循环剥离入度为 0 的节点。
   - 若剥离完毕后，仍有节点剩余 → 存在环。
4. **输出环信息**：将环中的特征名拼接成链，返回给前端。

### 4.3 级联状态标记规则（联动更新）

当某个特征被修改或状态发生变化时，系统必须自动维护下游特征的 `status`：

| 触发事件 | 系统自动执行的动作 |
| :--- | :--- |
| 特征 A 的 `formula` 被修改 | 递归查询所有直接或间接依赖 A 的特征（下游），将其 `status` 统一更新为 **`pending_recalc`**。 |
| 特征 A 被切换为 `deprecated` | 检查是否存在 `enabled` 的下游特征。若有，**阻止切换**，提示：“无法弃用 ‘A’，因为 ‘B’ 依赖它。请先停用或修改 B。” |
| 特征 A 从 `pending_recalc` 被手动确认已重算完成 | （由 DAG 调度模块调用接口回写）本模块提供 API 供 DAG 调用，将 `status` 由 `pending_recalc` 更新为 `enabled`，并回写 `latest_computed_date`。 |

### 4.4 数据质量自动监控规则

基于 DAG 回写的数据质量统计字段，系统自动执行以下监控逻辑（在 DAG 回写统计信息时触发）：

| 检测条件 | 系统自动行为 |
| :--- | :--- |
| 最新回写的 `data_completeness` < 80% | 将 `status` 自动更新为 **`data_anomaly`**，`data_anomaly_reason` 记录为“数据完整度低于80%，请检查数据源。” |
| `latest_computed_date` 距当前日期超过 5 个交易日 | 将 `status` 自动更新为 **`data_anomaly`**，`data_anomaly_reason` 记录为“超过5个交易日未更新，请检查 DAG 调度。” |
| `pending_cells_total` > `total_effective_cells * 0.2` | 标记为 `data_anomaly`，原因：“待计算格子数超过有效格子的20%，可能存在大规模计算积压。” |
| 数据质量恢复正常（如 `data_completeness` 回升至 ≥ 90%） | 自动将 `status` 由 `data_anomaly` 恢复为 `enabled`，清除 `data_anomaly_reason`。 |

## 五、核心操作流程（增删改查）

### 5.1 新增特征

| 步骤 | 操作人 | 系统行为 |
| :--- | :--- | :--- |
| 1 | 用户填写表单，点击「存为草稿」或「保存并启用」 | 前端进行基础格式校验 |
| 2 | — | 后端接收请求，执行完整的 KEPL 语法解析与依赖提取 |
| 3 | — | 后端执行循环依赖检测（若为 `enabled` 状态则强制检测；若为 `draft` 状态仅预警不阻塞） |
| 4 | — | 通过校验后，写入 `features` 表，生成唯一 ID |
| 5 | — | 返回成功，刷新列表页 |
| 6 | — | **（异步）** 系统向 DAG 调度模块发送“新增特征”通知，触发首次补数任务 |

### 5.2 编辑特征

| 限制条件 | 处理逻辑 |
| :--- | :--- |
| **目标实体不可修改** | 字段置灰，若前端篡改请求，后端拦截并返回 400 错误 |
| **特征英文名不可修改** | 编辑时英文名显示为只读文本，防止下游依赖断裂 |
| 修改公式后 | 后端重新解析 `depends_on`，并与旧值比对。若发生变化，自动将**本特征**及**所有下游特征**的 `status` 标记为 `pending_recalc` |
| 修改其他元数据（中文名、描述） | 不触发依赖重算，仅更新 `updated_at` |

### 5.3 删除特征（软删除）

> **原则：物理删除绝对禁止。** 删除特征会导致历史上依赖它的回测结果无法复现。

| 用户操作 | 系统行为 |
| :--- | :--- |
| 用户点击「弃用」或「删除」 | 检查该特征是否被其他 `enabled` 或 `draft` 状态的特征依赖。 |
| **若存在下游依赖** | 弹窗提示：“该特征被 [B, C] 依赖，无法删除。请先修改或停用依赖特征。” |
| **若不存在下游依赖** | 将 `status` 更新为 `deprecated`。列表页默认隐藏 `deprecated` 特征（用户可通过筛选查看）。 |
| **管理员强制归档** | 提供「归档」功能，将特征移至回收站（`status='archived'`），保留元数据但 DAG 完全忽略。 |

### 5.4 查询特征

| 查询场景 | 实现要点 |
| :--- | :--- |
| **列表分页查询** | 支持按 `target_entity`、`status` 筛选；支持按 `feature_name` / `display_name` 模糊搜索。按 `updated_at` 降序排列。 |
| **详情查询** | 返回完整元数据，包括 `depends_on`（上游）和 `depended_by`（下游，需反向查表组装）。 |
| **依赖关系查询** | 提供专用 API `/api/features/dependencies`，返回全量特征的邻接表（`{ name: [depends_on] }`），供前端绘制依赖关系图。 |
| **数据预览查询** | 接收 `feature_id`、`entity_code`（可选）、`page`、`page_size`。后端查询对应的特征宽表，返回该特征列的实际数值。**严禁一次性加载全量数据**。 |

### 5.5 状态手动切换

| 操作 | 系统逻辑 |
| :--- | :--- |
| `draft` → `enabled` | 再次执行循环依赖检测，通过后更新状态。DAG 在下一周期将纳入计算队列。 |
| `enabled` → `draft` | 若下游存在 `enabled` 特征，**禁止降级**，提示：“存在下游依赖，无法撤回。” |
| 手动触发「标记为重算」 | 不直接触发计算，仅将本特征及其下游的 `status` 改为 `pending_recalc`，等待 DAG 响应。 |

## 六、为 DAG 调度模块提供的数据接口（数据契约）

本模块不调度任务，但 DAG 调度模块需要读取本模块的数据来编排执行计划。以下接口为本模块**必须提供**的只读数据服务：

| 接口用途 | 输出数据结构 | 说明 |
| :--- | :--- | :--- |
| **获取待计算特征列表** | 返回所有 `status = 'enabled'` 或 `'pending_recalc'` 的特征，按 `target_entity` 分组，附带各自的 `depends_on` 和 `formula`。 | DAG 调度器据此构建拓扑执行层级。 |
| **获取特征依赖图谱** | 返回全量 `enabled` 特征的邻接表（JSON 格式）。 | DAG 调度器据此计算并行度与执行顺序。 |
| **获取特征计算参数** | 返回特征的 `target_entity`、`formula`、`default_lookback`（需关联函数表获取）。 | DAG 在执行计算任务时，需知道该特征属于哪个实体，以及需要拉取多长的历史窗口。 |
| **回写计算状态与统计（接收请求）** | 接收 DAG 发来的：`{ feature_name, latest_computed_date, total_effective_cells, missing_cells_total, pending_cells_total, data_completeness }` | 当 DAG 完成某特征的计算后，调用此接口回写统计字段。若计算成功，将 `pending_recalc` 更新为 `enabled`；若失败，保持 `pending_recalc` 并记录错误日志。 |

## 七、API 接口设计（概要）

| 方法 | 路径 | 功能 | 备注 |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/features` | 获取特征列表（分页 + 筛选） | 支持 `entity`、`status`、`keyword` 参数 |
| `GET` | `/api/features/{id}` | 获取单个特征完整信息 | 包含 `depended_by`（下游引用）和完整统计字段 |
| `GET` | `/api/features/dependencies` | 获取全量依赖关系邻接表 | 供前端画图 + DAG 调度器读取 |
| `POST` | `/api/features/validate` | 验证 KEPL 公式语法与依赖 | 不保存，仅返回校验结果与提取出的 `depends_on` |
| `POST` | `/api/features` | 新增特征（草稿/启用） | 触发全量校验 |
| `PUT` | `/api/features/{id}` | 编辑特征元数据或公式 | 触发依赖重解析与级联状态更新 |
| `PATCH` | `/api/features/{id}/status` | 切换状态（启用/停用/标记待重算） | 触发上下游校验 |
| `DELETE` | `/api/features/{id}` | 软删除（弃用） | 检查下游依赖，有则拦截 |
| `GET` | `/api/features/{id}/data` | 分页预览特征数值 | 参数：`entity_code`（选填）、`page`、`size` |
| `POST` | `/api/features/{id}/stats` | **（供 DAG 调用）** 回写数据质量统计字段 | 更新 `total_effective_cells`、`data_completeness` 等，触发自动质量监控规则 |
| `POST` | `/api/features/{id}/mark-pending` | 手动标记下游级联待重算 | 管理员/用户手动触发依赖刷新 |
