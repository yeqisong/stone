# K道量化平台 - DAG流程编排与节点注册中心模块开发设计方案


## 一、模块概述

### 1.1 模块定位

DAG流程编排与节点注册中心模块是K道量化平台的 **“流程编排中枢”** 。它由两大核心子模块构成：

| 子模块 | 职责 |
| :--- | :--- |
| **节点注册中心（Node Registry）** | 定义平台支持的所有节点类型（行情下载、特征计算等），规范节点的元数据、配置Schema、内部依赖子图结构，形成统一的“节点合约”标准。 |
| **DAG流程管理（Flow Manager）** | 通过可视化拖拽方式，将已注册的节点编排成可执行的DAG流程，管理流程的版本、Cron调度配置与生命周期。 |

**核心设计理念**：
- **节点即插件**：任何业务模块（特征、下载、回测等）只要遵循节点合约规范注册自身，即可被DAG流程使用，核心代码零修改。
- **流程即代码**：DAG流程定义以JSON结构化存储，支持版本管理、回滚和审计追溯。
- **配置与执行分离**：本模块只管理流程定义，实际执行由独立的调度引擎负责。
- **内部结构可观测**：每个节点通过元数据接口暴露内部依赖子图，在编排和执行时均可见。

## 二、节点注册中心（子模块一）

### 2.1 设计理念

节点注册中心是DAG流程编排的 **“基础设施层”** 。它定义了平台支持的所有节点类型，并建立了业务模块与DAG模块之间的 **“节点合约（Node Contract）”** 标准。

> **核心价值**：新增节点类型无需修改DAG核心代码。业务模块只要按照合约实现三个接口（元数据、执行、状态），即可自动被DAG流程识别和使用。

### 2.2 节点合约规范（三层接口）

每个业务模块（特征、下载等）若要被DAG流程调用，必须实现以下三个接口：

| 接口类别 | 接口路径 | 调用方 | 职责 | 返回内容 |
| :--- | :--- | :--- | :--- | :--- |
| **元数据接口（Metadata）** | `/dag/node-meta` | DAG前端 | 提供节点类型的基本信息、配置Schema、内部依赖子图 | `{ type_id, display_name, icon, color, config_schema, internal_subgraph, config_options }` |
| **执行接口（Execution）** | `/dag/execute` | DAG调度引擎 | 执行节点的业务逻辑（下载/计算/回测等） | `{ execution_id, status }` |
| **状态/进度接口（Status）** | `/dag/node-status` 或回调 | DAG调度引擎 | 获取或接收节点的层级化执行进度 | `{ overall_percent, sub_tasks: [...] }` |

## 三、DAG流程管理（子模块二）

### 3.1 设计理念

DAG流程管理模块基于已注册的节点类型，提供**可视化拖拽编排**能力，将原子节点组合成可执行的业务流程，并管理流程的版本、调度配置与全生命周期。

> **核心价值**：业务用户无需编写代码，通过拖拽即可构建复杂的量化流水线（如：每日收盘后 → 下载行情 → 计算特征 → 训练模型 → 生成报告）。

### 3.2 数据模型设计

#### 3.2.1 流程定义表：`dag_flows`

| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 主键 |
| `flow_name` | VARCHAR(128) | UNIQUE, NOT NULL | 流程名称 |
| `description` | TEXT | — | 流程描述 |
| `cron_expression` | VARCHAR(64) | — | Cron表达式，为空表示手动触发 |
| `timezone` | VARCHAR(32) | DEFAULT 'Asia/Shanghai' | 时区 |
| `status` | VARCHAR(16) | DEFAULT 'draft' | 状态：`draft` / `enabled` / `disabled` / `archived` |
| `flow_graph` | JSON | NOT NULL | 流程拓扑：`{ nodes: [...], edges: [...] }` |
| `node_configs` | JSON | — | 节点配置：`{ node_id: { ...params } }` |
| `version` | INT | DEFAULT 1 | 版本号，每次修改自动+1 |
| `created_by` | VARCHAR(64) | — | 创建人 |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新时间 |
| `last_executed_at` | DATETIME | — | 最近一次执行时间（由调度引擎回写） |
| `last_execution_status` | VARCHAR(16) | — | 最近一次执行状态 |

**`flow_graph` 示例**：
```json
{
  "nodes": [
    { "id": "node_1", "type": "download", "x": 100, "y": 50 },
    { "id": "node_2", "type": "feature", "x": 350, "y": 50 }
  ],
  "edges": [
    { "source": "node_1", "target": "node_2" }
  ]
}
```

**`node_configs` 示例**：
```json
{
  "node_1": {
    "data_type": "stock",
    "entity_codes": null,
    "force": false
  },
  "node_2": {
    "feature_name": "bias_5d",
    "entity_codes": null,
    "force_recompute": false
  }
}
```

#### 3.2.2 版本历史表：`dag_flow_versions`

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | BIGINT | 主键 |
| `flow_id` | BIGINT | 关联 `dag_flows.id` |
| `version` | INT | 版本号 |
| `flow_graph` | JSON | 该版本的流程拓扑快照 |
| `node_configs` | JSON | 该版本的节点配置快照 |
| `change_log` | TEXT | 变更说明（用户填写） |
| `created_by` | VARCHAR(64) | 修改人 |
| `created_at` | DATETIME | 快照时间 |

### 3.4 流程校验规则

| 校验项 | 说明 | 错误提示 |
| :--- | :--- | :--- |
| **DAG无环** | 图中不能存在循环依赖 | “检测到循环依赖：node_1 → node_2 → node_1” |
| **单一入口** | 有且仅有一个入度为0的节点 | “流程必须有且仅有一个起始节点” |
| **至少一个出口** | 至少有一个出度为0的节点 | “流程必须至少有一个终止节点” |
| **节点已配置** | 所有节点的必填参数已填写 | “节点 node_1 缺少必填参数：feature_name” |
| **参数有效** | 参数值符合Schema约束 | “特征名称 ‘xxx’ 不存在，请从列表中选择” |
| **节点类型存在** | 引用的节点类型已注册 | “节点类型 ‘xxx’ 未注册，请检查” |
| **数据类型匹配** | 上下游输出/输入类型兼容 | “特征计算节点不能直接连接在回测节点之后” |

### 3.5 版本管理机制

| 规则 | 说明 |
| :--- | :--- |
| 触发条件 | 修改流程名称、描述、Cron、流程图、节点配置 → 生成新版本 |
| 不触发条件 | 仅启用/停用流程、仅执行流程 → 不生成版本 |
| 版本回滚 | 选择历史版本 → 一键回滚 → 自动生成新版本（change_log标注回滚） |
| 执行绑定 | 每次执行记录使用的版本号，确保可复现性 |


## 四、与调度执行模块的协作约定

### 4.1 信息传递

| 方向 | 内容 |
| :--- | :--- |
| **本模块 → 调度引擎** | 流程定义（`flow_graph` + `node_configs` + `cron_expression` + `version`） |
| **调度引擎 → 本模块** | 执行结果回写（`last_executed_at` + `last_execution_status`） |

### 4.2 执行触发方式

| 方式 | 说明 |
| :--- | :--- |
| **Cron定时触发** | 调度引擎监听Cron表达式，到达触发时间执行 |
| **手动触发** | 用户在前端点击 **[运行]** 按钮 |

### 4.3 执行时的节点调用流程

```
调度引擎解析流程定义
        │
        ▼
按拓扑顺序确定节点执行顺序
        │
        ▼
对于每个节点：
  1. 根据 node.type 查询 dag_node_types 表
  2. 获取 service_name + api_base_url + execution_endpoint
  3. 构建执行请求（含 node_configs + 上下文）
  4. 调用业务模块的 execution_endpoint
  5. 接收进度回调（通过 ProgressCallback）
  6. 将进度转推 WebSocket 给前端
        │
        ▼
所有节点执行完毕，回写流程执行状态
```

## 六、错误码定义

| 错误码 | 说明 | 处理建议 |
| :--- | :--- | :--- |
| `DAG_001` | 流程名称已被占用 | 修改名称后重试 |
| `DAG_002` | 流程图中存在循环依赖 | 调整连线方向 |
| `DAG_003` | 流程无起始节点 | 添加一个入度为0的节点 |
| `DAG_004` | 流程无终止节点 | 确保至少一个节点出度为0 |
| `DAG_005` | 节点配置不完整 | 填写所有必填参数 |
| `DAG_006` | 节点类型不存在 | 检查节点类型是否已注册 |
| `DAG_007` | 流程已被引用，无法删除 | 先解除引用关系 |
| `DAG_008` | Cron表达式不合法 | 使用标准Cron格式 |
