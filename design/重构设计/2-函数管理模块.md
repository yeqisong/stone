# K道量化平台 - 函数管理模块开发设计方案
## Function Management Module - Development Design Specification v1.0

## 一、模块概述

### 1.1 模块定位

函数管理模块是 KEPL（Keda Expression & Programming Language）语言体系的 **“原子层”**。它负责注册、存储、校验和管理所有可在特征公式中调用的 **“算子（Operator）”**。用户在此模块中定义的函数，将在 **“特征管理”** 模块中被引用，用于构建基础特征和复合特征。

### 1.2 核心目标

1. 提供可视化的 Python 函数注册、编辑、版本管理界面。
2. 建立严格的代码安全沙箱与向量化性能校验机制。
3. 实现函数的统一存储与动态加载，供 DAG 调度器和公式解析器调用。

### 1.3 技术栈（推荐）

| 层级 | 技术选型 | 说明 |
| :--- | :--- | :--- |
| 前端框架 | Vue 3 / React 18 | 组件化开发，支持代码编辑器集成 |
| 代码编辑器 | Monaco Editor（VS Code 内核） | 提供 Python 语法高亮、自动缩进、错误波浪线 |
| 后端框架 | FastAPI / Spring Boot | RESTful API 接口 |
| 数据库 | PostgreSQL / MySQL | 存储函数元数据与源码 |
| 沙箱执行 | Python `subprocess` + `resource` 模块 | 隔离执行用户代码，限制 CPU/内存/时间 |
| 代码分析 | Python `ast`（抽象语法树） | 静态扫描危险代码与函数签名 |

## 四、校验规则详细设计

### 4.1 前端校验（即时反馈，提高体验）

| 校验项 | 触发时机 | 实现方式 | 失败提示 |
| :--- | :--- | :--- | :--- |
| 函数英文名格式 | 输入框失焦 | 正则匹配 | “英文名必须是小写字母开头，仅包含小写字母、数字、下划线。” |
| 英文名唯一性 | 输入框失焦 | 异步请求后端接口 `POST /functions/check-name` | “函数英文名已被占用，请修改。” |
| 参数名格式 | 每新增/编辑一行参数时 | 正则匹配 | “参数名必须是小写字母开头，仅包含小写字母、数字、下划线。” |
| 参数列表中不能有重名 | 提交时 | 前端遍历数组 | “参数名 ‘xxx’ 重复，请修改。” |
| 至少有一个参数 | 提交时 | 校验数组长度 >0 | “请至少定义一个输入参数。” |
| 第一个参数类型为 `field` | 提交时 | 检查 `parameter_schema[0].type === 'field'` | “第一个参数必须为 `field` 类型（作为数据入口）。” |
| 函数体是否包含 `def` | 提交时 | 正则 `/\bdef\s+\w+\s*\(/` | “函数体必须包含 `def 函数名(参数):` 的定义。” |
| 代码编辑器基本语法（红色波浪线） | 实时编辑 | Monaco 自带语法检查 | 原生报错显示在编辑器行号旁（不阻塞保存） |

### 4.2 后端校验（安全闸门）

#### 4.2.1 第一层：语法与安全（静态分析）

| 校验项 | 技术实现 | 失败处理 |
| :--- | :--- | :--- |
| Python 语法正确性 | `compile(function_code, '<string>', 'exec')` | 捕获 `SyntaxError`，返回“第 X 行：具体错误信息”给前端 |
| 函数签名：第一个参数必须命名为 `df` | `ast.parse` → 遍历 `FunctionDef` 节点，检查 `args.args[0].arg == 'df'` | “函数第一个参数必须命名为 `df`（代表传入的数据框），请修改。” |
| 返回值类型检查（轻量） | AST 扫描是否有 `Return` 节点，且返回值不是常量 | 若直接 `return 1`，提示“特征函数返回值应为 Series 或 DataFrame，而非标量。” |
| 危险代码拦截 | AST 遍历检测 `Call` 节点：<br>• `eval`、`exec`、`compile`<br>• `__import__`<br>• `os.system`、`os.popen`<br>• `subprocess.call`<br>• `open`（文件读写） | 直接 **拒绝入库**，返回：“检测到不安全的系统调用（如 eval/os），此函数禁止入库。” |

#### 4.2.2 第二层：性能与向量化（动态测试 — 试运行）

| 校验项 | 技术实现 | 判定阈值 | 处理方式 |
| :--- | :--- | :--- | :--- |
| 性能基准测试 | 在隔离子进程中执行函数：<br>1. 生成 10,000 行测试 DataFrame（含 `open/close/high/low/volume`）<br>2. 调用用户函数 3 次，取平均耗时 | • **< 50ms**：✅ 优秀<br>• **50~500ms**：⚠️ 警告<br>• **> 500ms**：❌ 不通过 | 警告时弹窗提示，但允许保存（标记 `validation_status=warning`）；<br>不通过时强制拦截，并提供优化建议（如“建议使用 `rolling` 替代 `for` 循环”）。 |
| 数据列存在性 | 试运行中，用 `df[field]` 访问字段，捕获 `KeyError` | — | 返回：“字段 ‘xxx’ 不存在，请检查参数默认值或数据列名。” |
| 超时保护 | 子进程设置 `timeout=5` 秒 | 5 秒未返回则 `TimeoutExpired`，强制终止 | “函数执行超时（超过 5 秒），请优化算法或检查是否存在死循环。” |
| 内存限制 | 使用 `resource.setrlimit` 限制子进程内存上限 256MB | 超过则被 OS 终止 | “函数执行内存超限（>256MB），请优化数据加载方式。” |

**关于“向量化校验”的补充说明**：  
静态扫描无法 100% 确认代码是否向量化，因此**性能基准测试是唯一的可靠手段**。用户若写 `df.apply(lambda x: x.mean())`，虽然表面上可读性尚可，但实际是 Python 层逐行循环，耗时通常在 200~800ms 之间，会被性能测试拦截并提示优化。这比任何静态分析都有效。


## 五、存储与调用机制

### 5.1 存储流程

用户点击 **[保存并发布]** 后，后端按以下顺序执行：

1. **执行所有校验规则**（第 4.2 节），任一失败则中断存储并返回错误。
2. **判断操作类型**：
   - 若 `id` 不存在（新增）：插入 `functions` 表，`version=1`，`status='published'`。
   - 若 `id` 存在且 `status='draft'`（编辑草稿）：直接覆盖 `function_code`，`version` 不变。
   - 若 `id` 存在且 `status='published'`（编辑已发布函数）：强制要求填写“版本更新说明”，执行以下原子操作：
     a. 插入 `function_versions` 快照表（记录旧代码）。
     b. 更新 `functions` 表：`version = version + 1`，覆盖 `function_code`，`updated_at = NOW()`。
3. **编译并缓存函数对象**：将 Python 代码编译为 `callable` 对象，存入内存缓存（如 Redis，key = `func:{function_name}:{version}`），供 DAG 调度时快速调用，避免每次重复编译。

### 5.2 调用流程（DAG 执行时）

1. **特征引擎解析公式**（如 `ma(close, 5)`），提取 `function_name='ma'` 和参数 `field='close', window=5`。
2. **查询缓存**：先尝试从 Redis 加载 `func:ma:latest`；若未命中，查询 `functions` 表，加载 `function_code`，编译后存入 Redis。
3. **准备数据**：根据 `default_lookback` 和实际 `window` 的较大值，从宽表拉取历史数据（DataFrame）。
4. **执行函数**：调用 `ma(df, 'close', 5)`，取返回值的最后一行作为今日特征值。
5. **结果回填**：将值写入 `feature_*` 宽表，对应 `(trade_date, entity_code)` 的单元格。

### 5.3 版本锁定机制（重要）

在“特征注册”时，系统记录的不仅仅是函数名，还包含**函数版本号**（如 `ma@v2`）。这样做的好处是：

- 当用户修改 `ma` 函数发布 v3 版本时，已有特征（如 `bias_5d`）仍使用 v2 版本计算，**历史回测结果不会被颠覆**。
- 只有新注册的特征才会使用最新版本（`@latest` 或指定版本）。

## 八、非功能性需求

1. **安全性**：子进程沙箱隔离，用户代码无权访问系统文件、网络、环境变量。
2. **性能**：函数编译结果缓存至 Redis，避免重复编译（命中率 >95%）。
3. **可观测性**：记录每次函数调用的耗时、错误率到监控系统（如 Prometheus），当平均耗时超过阈值时告警。
4. **兼容性**：系统内置函数（如 `ma`、`rsi`）不存储在 `functions` 表中，由内核硬编码实现，但**在公式解析器中与自定义函数同等调用**（用户无感知差异）。
