# K道量化平台 - 行情下载优化模块开发设计方案


## 一、模块概述

### 1.1 模块定位

行情下载优化模块是 K道量化平台的 **“数据准备层”** 。它建立在已有的**数据适配层**（适配 OurStick、AK Share 等不同数据源）和**数据存储层**（已实现个股、ETF、指数、基本面四类行情存储）之上，提供统一的数据下载服务接口。

**核心定位**：在 DAG 调度模块中，行情下载模块表现为 **“一个独立的数据准备节点”** 。DAG 只负责触发该节点并接收完成信号，节点内部的下载策略、数据源切换、增量更新等所有逻辑变化，**均不对外暴露**。

> **边界声明**：本模块 **只负责“如何下载”和“如何存储”**，不负责“何时下载”和“进度如何展示”。下载任务的触发由 DAG 调度模块按编排好的流程调用本模块的接口完成。本模块对外提供 **且仅提供两个稳定接口**：按日下载（`download_daily`）和按时间段下载（`download_range`）。

### 1.2 模块在整体架构中的位置


| 组件 | 状态 | 说明 |
| :--- | :--- | :--- |
| **数据适配层** | ✅ 已实现 | 适配 OurStick、AK Share 等不同数据源，提供统一的数据获取接口 |
| **个股行情存储** | ✅ 已实现 | 日线数据已入库 |
| **ETF行情存储** | ✅ 已实现 | 日线数据已入库 |

### 1.4 核心设计原则

| 原则 | 说明 |
| :--- | :--- |
| **接口稳定性** | 对外仅暴露 `download_daily` 和 `download_range` 两个接口，永不变化。内部所有演进不影响外部调用方。 |
| **内部自包含** | 数据源的增减、下载策略的变化、重试机制的优化，全部在模块内部处理，DAG 无须感知。 |
| **增量优先** | 默认只下载缺失的数据，避免重复下载已存在的数据，节省时间和 API 配额。 |
| **幂等性** | 同一日期范围、同一数据类型的重复下载请求，不产生脏数据（UPSERT 语义）。 |
| **数据源容错** | 主数据源失败时自动切换备用数据源，对调用方透明。 |
| **无外部依赖** | 模块不依赖 WebSocket、消息队列等外部组件，保持纯粹的数据下载与存储职责。 |


## 二、对外接口定义（模块门面）

这是本模块**对外暴露且仅暴露的两个接口**。DAG 调度模块仅需了解这两个接口的语义，模块内部的所有变化（数据源切换、下载策略优化、新增数据类型）对外完全透明。

### 2.2 接口一：按日下载

```python
def download_daily(
    self,
    data_type: DataType,            # 数据类型：stock / etf / index / fundamental
    date: str,                      # 交易日，如 '2026-06-27'
    entity_codes: Optional[List[str]] = None,  # None 表示全量实体
    force: bool = False,            # 是否强制覆盖已存在的数据
    progress_callback: Optional[ProgressCallback] = None
) -> DailyDownloadReport:
    """
    下载指定数据类型在指定日期的数据，并写入存储。
    
    内部自动完成：
    1. 检查该日数据是否已存在（若 force=False 且已存在，直接跳过）
    2. 根据数据类型选择对应的适配器（如 stock → OurStick 个股接口）
    3. 下载数据并进行格式标准化
    4. 写入对应的数据表（UPSERT）
    5. 更新下载状态日志
    
    返回：DailyDownloadReport
        - data_type: str
        - date: str
        - total_entities: int          # 应下载的实体总数
        - success_entities: int        # 成功下载的实体数
        - skipped_entities: int        # 已存在且未强制下载的实体数
        - failed_entities: List[str]   # 失败的实体列表
        - data_source_used: str        # 实际使用的数据源（如 'ourstick'）
        - execution_time_ms: int
        - status: 'completed' | 'partial' | 'failed' | 'skipped'
    """
    pass
```

### 2.3 接口二：按时间段下载

```python
def download_range(
    self,
    data_type: DataType,            # 数据类型
    start_date: str,                # 起始日期
    end_date: str,                  # 结束日期
    entity_codes: Optional[List[str]] = None,  # None 表示全量实体
    force: bool = False,            # 是否强制覆盖已存在的数据
    progress_callback: Optional[ProgressCallback] = None
) -> RangeDownloadReport:
    """
    下载指定数据类型在指定日期范围内的数据，并写入存储。
    
    内部自动完成：
    1. 检查该日期范围内哪些日期已有数据（增量检测）
    2. 仅下载缺失的日期（若 force=True 则全部重下）
    3. 按日期分块（chunk）执行，避免内存溢出和 API 限频
    4. 每个 chunk 内并发下载多个实体
    5. 增量写入存储，失败自动重试
    6. 记录下载历史
    
    返回：RangeDownloadReport
        - data_type: str
        - date_range: Tuple[str, str]
        - total_days: int              # 总天数
        - total_entities: int          # 应下载的实体总数
        - total_cells: int             # 总格子数（天数 × 实体数）
        - success_cells: int           # 成功下载的格子数
        - skipped_cells: int           # 已存在且未强制下载的格子数
        - failed_cells: int            # 失败的格子数
        - data_source_used: str        # 实际使用的数据源
        - execution_time_ms: int
        - status: 'completed' | 'partial' | 'failed'
        - error_details: Optional[Dict]
    """
    pass
```

### 2.4 接口参数约定

| 参数 | 说明 | 校验规则 |
| :--- | :--- | :--- |
| `data_type` | 数据类型 | 必须是 `stock` / `etf` / `index` / `fundamental` 之一 |
| `date` / `start_date` / `end_date` | 交易日 | 必须是有效交易日，`start_date <= end_date` |
| `entity_codes` | 实体代码列表 | 若为 `None`，自动展开为该数据类型下的全量实体列表 |
| `force` | 强制重下 | `True` 时忽略已存在的数据，重新下载并覆盖；`False` 时跳过已存在的数据 |
| `progress_callback` | 进度回调 | 由调用方（DAG 调度层）传入，用于获取进度并自行决定如何推送 |

### 3.3 数据源路由与故障转移

```python
class DataSourceRouter:
    # 数据源优先级配置
    SOURCE_PRIORITY = {
        'stock': ['ourstick', 'akshare'],      # 个股主用 OurStick，备用 AK Share
        'etf': ['ourstick', 'akshare'],
        'index': ['ourstick', 'akshare'],
        'fundamental': ['akshare', 'ourstick'] # 基本面主用 AK Share
    }
    
    def get_optimal_source(self, data_type: DataType) -> str:
        """
        根据数据源健康状态和优先级，选择最优数据源。
        健康状态包括：最近成功率、平均响应时间、是否在维护窗口等。
        """
        # 按优先级遍历，返回第一个健康的数据源
        for source_name in self.SOURCE_PRIORITY[data_type.value]:
            if self._is_healthy(source_name):
                return source_name
        # 若所有源都不健康，返回默认源并记录警告
        return self.SOURCE_PRIORITY[data_type.value][0]
    
    def record_result(self, source_name: str, success: bool, response_time_ms: int):
        """记录每次下载的结果，用于健康状态统计"""
        pass
    
    def _is_healthy(self, source_name: str) -> bool:
        """判断数据源是否健康：成功率 > 80%，且最近5次请求未全部失败"""
        pass
```

### 3.4 下载执行流程

当 `download_range('stock', '2026-06-01', '2026-06-27')` 被调用时，内部执行流程如下：

```python
def _execute_download(self, data_type, start_date, end_date, entity_codes, force, callback):
    # 1. 增量检测：找出缺失的日期
    if not force:
        target_dates = self.detector.get_missing_dates(data_type, start_date, end_date, entity_codes)
    else:
        target_dates = get_trading_days(start_date, end_date)
    
    if not target_dates:
        return RangeDownloadReport(status='skipped', message='所有数据已存在')
    
    # 2. 按日期分块（每块10天，避免API限频）
    chunks = chunk_dates(target_dates, chunk_days=10)
    
    # 3. 获取最优数据源
    source = self.router.get_optimal_source(data_type)
    
    # 4. 逐块下载
    results = []
    for chunk in chunks:
        chunk_result = self._download_chunk(
            data_type, chunk, entity_codes, source, force, callback
        )
        results.append(chunk_result)
        # 块间休眠，避免触发数据源限频
        time.sleep(0.5)
    
    # 5. 汇总结果
    return self._aggregate_results(results)
```

## 四、进度暴露机制

### 4.1 设计原则

行情下载模块**不主动推送进度**，而是通过 **`ProgressCallback` 回调接口** 向外暴露进度信息。由调用方（DAG 调度模块）决定如何将进度转换为 WebSocket 消息、日志或数据库记录。

### 4.2 回调接口定义

```python
class ProgressCallback:
    def on_start(self, total_days: int, total_entities: int, total_cells: int):
        """任务启动时调用"""
        pass
    
    def on_chunk_start(self, chunk_index: int, total_chunks: int, date_range: Tuple[str, str]):
        """每个日期分块开始下载时调用"""
        pass
    
    def on_entity_progress(
        self, 
        entity_code: str, 
        processed: int, 
        total: int, 
        current_date: str
    ):
        """下载过程中，每完成一个实体时调用"""
        pass
    
    def on_chunk_complete(self, chunk_index: int, success_count: int, failed_count: int, elapsed_ms: int):
        """每个分块完成时调用"""
        pass
    
    def on_data_source_switched(self, old_source: str, new_source: str, reason: str):
        """数据源切换时调用（如主源失败切备用源）"""
        pass
    
    def on_task_complete(self, result: DownloadReport):
        """全部任务完成时调用"""
        pass
    
    def on_task_failed(self, error: Exception):
        """任务失败时调用"""
        pass
    
    def is_cancelled(self) -> bool:
        """返回 True 表示任务已被取消，模块应优雅终止"""
        return False
```

## 五、与特征计算模块的对称性设计

| :--- | :--- | :--- |

| **进度暴露** | `ProgressCallback` 回调 | `ProgressCallback` 回调 |

| **DAG 视角** | 一个黑盒节点 | 一个黑盒节点 |


## 六、错误处理与容错

| 异常类型 | 处理策略 | 返回状态 |
| :--- | :--- | :--- |
| **数据源不可用** | 自动切换到备用数据源，切换成功则继续，全部失败则终止 | `status='partial'` 或 `'failed'` |
| **单个实体下载失败** | 记录失败实体，继续下载其他实体 | `status='partial'`，`failed_entities` 列表记录 |
| **API 限频（429）** | 指数退避重试（1s → 2s → 4s），最多3次 | 重试成功则继续，失败则记录该实体失败 |
| **网络超时** | 重试3次，每次超时时间递增 | 同限频处理 |
| **日期不在交易日历中** | 跳过该日期，继续下载其他日期 | `status='partial'`，记录跳过日期 |
| **数据格式异常**（如返回空数据） | 记录失败，不写入存储 | `failed_entities` 列表记录 |
| **用户取消任务** | 检测 `callback.is_cancelled()`，优雅终止 | `status='cancelled'` |

## 八、与 DAG 调度模块的协作约定

```
┌─────────────────────────────────────────────────────────────────┐
│                      DAG 调度模块                              │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  1. 流程编排：定义“行情下载节点”在流程中的位置          │   │
│  │  2. 任务触发：按编排调用 download_daily / range          │   │
```

## 九、实施建议（优先级拆分）

| 阶段 | 功能范围 | 预估工作量 |
| :--- | :--- | :--- |
| **Phase 1（MVP）** | 两个对外接口骨架 + 单日下载 + 写入存储（已有适配器调用） | 3~4 人天 |
| **Phase 2（增量检测）** | 增量检测器 + 跳过已存在数据 + 下载历史记录 | 2~3 人天 |
| **Phase 3（优化与容错）** | 分块下载 + 并发控制 + 数据源路由 + 故障转移 | 3~4 人天 |
| **Phase 4（进度与监控）** | ProgressCallback 接口 + 健康状态统计 + 日志 | 2 人天 |


## 十、总结

本模块与特征计算模块共同构成 DAG 调度模块的 **“数据准备-特征计算”** 双节点体系：

- **行情下载模块**：负责将原始数据从外部数据源拉取到本地存储。
- **特征计算模块**：负责将本地存储的原始数据转换为量化特征。

两者对外接口完全对称（`*_daily` / `*_range`），进度暴露机制完全一致，且内部变化对外完全透明。DAG 调度模块可以以统一的模式编排这两个节点，实现 **“数据驱动特征，特征驱动模型”** 的完整链路。
