# 14 · 实时页（盘中作战台）

> v3.28.0（2026-11-28）。把依靠盘中实时数据的三块功能——选股页「分时市值」树图、大盘页子页
> 「实时盘」`#/kr`、个股页「盘中雷达 / 买点检查」——收进一个一级页面 `#/rt`，并按交易纪律顺序重新布局。
> **后端零新端点**；权限新增一个容器节点 `research.realtime.view`；旧链接全部重定向不失效。

## 1. 需求与依据

用户诉求：「加一个【实时】一级页面，把依靠盘中实时数据的放在这一个页面中，按我的交易习惯合理布局。」

布局依据不是臆测，全部来自项目里已经固化的纪律：

| 交易习惯 | 出处（项目内） | 对布局的要求 |
|---|---|---|
| 纪律先行：市场闸门 × regime × 情绪、仓位/熔断/T+1 决定「今天能不能做」 | `skills/pre-trade-checklist`、`skills/drawdown-discipline`、`buy_check.live_gate` | 第一眼必须是闸门结论，而不是图表 |
| 先风险后机会 | 雷达原本就是「持仓信号」排在「买点候选」前；`intraday_signal`「只对持仓给动作，仓位高于目标不给买入」 | 持仓区在机会区左边 |
| 流程不是预测：提醒 → 解读 → 结构 → 风控 → 记录，不许从提醒直接跳到下单 | `IntradayPlaybook`（盘中执行卡 5 步） | 候选只是入口，必过四道闸门（市场/板块/结构/风险） |
| 板块确认是四道闸门之一 | `buy_check.sector_gate` | 资金地图 / 板块雷达是「验证板块」用的，不是第一眼内容 |
| 数据缺失本身也是检查结果 | `skills/pre-trade-checklist`「注意」 | 拉取失败必须在界面上标出来，不能静默 |
| 熔断看收盘净值，不看盘中 | `skills/drawdown-discipline` | 闸门只展示，盘中不改买入行为（沿用 design/13 §9.2 的决策） |

## 2. 布局：一条决策线 + 三个决策区 + 一条分析带

```
┌ 决策线 ─ 休市 · 显示 11-27（最近交易日）数据 · 更新 20:31 ─ 开仓闸门[警戒] 市场闸门走平 ─ 开新仓[禁止] 仓位 85% 高于目标 ─ 今日异动 0 ─┐
├─────────────────────── 盘面 ───────────────────────┬────────────── 持仓 ──────────────┬──────── 机会 ────────┤
│ ① 先看环境：能不能做                                 │ ② 先处理风险：止损/减仓/持有        │ ③ 后找机会：候选→闸门  │
│ 指数分时 4 小图 · 盘面宽度 · 两市成交/预估 · 今日异动  │ 持仓信号（按严重度）· 关注池雷达表   │ 闸门结论 · 候选/观察    │
│                                                     │ （持仓置顶，列宽自适应）             │ · 被拦时给「下一步」    │
├─────────────────────────────────────────────────────┴───────────────────────────────────┴───────────────────────┤
│ 分析带：[资金地图] 指数分时 · 板块与资金 · 涨停梯队 · 量能与情绪                                        [放大] │
│ 资金地图 = 分时市值树图 + 行业资金流（原选股页分时模式）                                                       │
└──────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

从上到下、从左到右就是决策顺序：**能不能做 → 环境怎样 → 先处理哪只持仓 → 有没有可买的 → 板块验证**。

- **决策线**（`RtDecisionStrip`）：时段 + 数据所属交易日、开仓闸门（`/api/market/realtime` 的 `gate`）、
  开新仓（`/api/buy/candidates` 的 `allowed` + `state` 摘要）、今日异动数。闸门三态配色与 TradeGuard /
  MarketSentiment 一致：开放=下跌绿、谨慎=warning、关闭=error（关闸是「停」不是「涨」）。
- **盘面区**（`RtMarketZone`，列宽 1.15）：四张指数小图（点开在分析带看大图）、宽度比例条 + 成交/预估、
  今日盘面异动流。情绪轨迹、量能对比等深度图表放分析带，这里只留「一眼判断环境」的东西。
- **持仓区**（`RtHoldingsZone`，列宽 1.15）：持仓动作行（止损 → 减仓 → 观察 → 持有）置顶，雷达表持仓优先。
- **机会区**（`RtOpportunityZone`，列宽 1）：闸门结论 → 买点候选 → 观察候选；点行打开买点检查弹窗（沿用
  `BuyCheck`）。**被拦时给出下一步**：`state.allow_new_buy=false`（仓位/纪律类）→「去持仓处理」，
  否则（市场闸门类）→「今天只管持仓」。
- **分析带**（`RtAnalysisBand`）：资金地图（`TreemapView` embedded）默认，可切指数分时 / 板块与资金 /
  涨停梯队 / 量能与情绪；「放大」收起三区让分析带占满。树图叶子点击原地弹「买点检查 / 个股详情」，
  不跳离实时页。

## 3. 数据与刷新

| 数据 | 端点 | 权限节点 | 交易时段 | 收盘后 |
|---|---|---|---|---|
| 盘面聚合 | `GET /api/market/realtime` | `research.market.view` | 15s | 60s |
| 连板高度历史 | `GET /api/market/realtime/zt-history` | 同上 | 5 分钟 | 5 分钟 |
| 盘中雷达 | `GET /api/stock/radar` | `research.radar.view` | 15s | 60s |
| 买点候选 | `GET /api/buy/candidates` | 同上 | 60s | 5 分钟 |
| 分时市值树图 | `GET /api/treemap_intraday` | `research.treemap.view` | TreemapView 自带 60s / 生成中 5s | 同左 |

- 轮询归 `RealtimeView`（页面级），分区只接收 props，不在各处重复请求。时段以盘面接口的 `session` 为准
  （含节假日），拿不到时按客户端时钟粗判（`localSession`，只用来决定快慢）。
- **失败不静默**：盘面 / 雷达 / 候选拉取失败都保留上一帧并在界面标出（决策线「刷新失败」、分区头部红色 chip）。
- 盘中提醒（`it%`）经 WS 到达即补刷一次雷达（5s 节流）——watcher 10s 一轮，比 15s 轮询更早看到异动。
- **数据所属交易日**：盘前/休市日各源都回退成上一交易日的整段数据，缓存更新时间不等于数据时间。
  决策线显示「显示 <最近交易日>（最近交易日）数据 · 更新 HH:MM:SS」；梯队/资金流/情绪轨迹各自标注数据日期；
  资金地图的日期跟盘面 `data_date` 走（周六打开不再是「今日暂无快照」），用户手动选过日期后不再跟随。

## 5. 权限

- 新增**容器节点** `research.realtime.view`（menu，无父，route `rt`），只管一级入口。
- 三个分区不新增端点，继续由既有节点**二次控制**：盘面区与分析带图表 tab = `research.market.view`；
  资金地图 = `research.treemap.view`；持仓区/机会区 = `research.radar.view`。缺节点的分区不渲染，
  布局自动重排（单区占满 / 两区对半）。
- 默认授予 admin / operator / trader / analyst / viewer（全市场共享，非 personal，非 support_only）；
  support 不授。只授容器码的自定义角色看得到空壳、拿不到任何数据（没有任何端点归容器码）。
- 旧库迁移：`seed_auth` 启动幂等播种，重启即生效；未授新码的旧角色分区 API 照常可用，只是一级入口不显示。
- 测试：`tests/unit/test_realtime_page_permission.py`（节点形态 / 角色矩阵 / 有权通过 + 无权空壳 / 分区端点不被容器码截胡）。

教训：

1. **截图核对不可省**。纯看「构建通过 + 测试通过」时下面这些全部漏掉，全是看了真实数据截图才发现的：
   迁出时把 `yiNum` 的 `/1e8` 弄丢（资金流 y 轴画成了「元」）、漏掉挂载时的 `loadHist()` 首调（历史图 5 分钟后才出现）、
   栅格 4 列放了 5 个元素、分析带放大后树图画布不跟。迁移旧代码时**逐个函数对一遍语义**，不要凭印象重写。
2. **非交易日 + 后端冷缓存是必测场景**：周六一眼暴露「地图默认取今天 → 今日暂无快照」；合并后重启 8000 的头一两分钟
   缓存是空的（`asof` 为空、各源还没回来），决策线只剩一个光秃秃的日期、地图又回到「今天」——这两项在交易日 + 热缓存下永远看不到。
   修法：没有数据时点就明说「后台采集中…」并给预计时长；地图日期兜底改「最近工作日」，缓存变热后自动切准。
3. **「被拦住」是纪律页面最常见的状态**，不是边角 case：机会区被禁时的空白比有候选时更该设计。
4. 并行会话各自动同一块代码时，合并前先 `git worktree list` + 看对方工作树的未提交 diff，能提前发现「我删的文件对方在改」。
5. 工作树里跑测试：Agent 沙箱要挂 `<根>/venv`（软链即可）；连库的「单元测试」读 `.env` 取密码，没有 `.env`
   会落到默认口令——按分支策略显式把 `DATABASE_URL*` 指到 `stone_test` 再跑。

## 9. v3.29.0 审查修复与体验优化（2026-11-28 增补）

全链路复盘（URL/路由 → 个人监测/提醒 → 宏观盘面/资金/风向）后的逐项修复，全部在 `feat/rt-review` 一并合入。
权限零新码：今日盘中提醒块复用既有 `risk.alerts.view`（`/api/risk/alerts?intraday=true`），其余均为展示层/口径修复。

**路由 / URL**

- **放大态与指数分时选中进 URL**：`/rt?tab=idx&idx=399006&zoom=1`——此前放大后刷新回三区、分享链接还原不了选中指数。
  `nav.rtZoom/rtIdx` 进 store，`syncHash` 组查询串，`parseHash → enterRealtime(tab, {zoom, idx})` 还原；旧链接重定向不传 opts → 复位。
- **nav.js 补监听 `hashchange`**：应用原先只监听 `popstate`，同页地址栏改 hash（粘贴链接、程序化 `location.hash=`）
  应用不响应（Playwright 验收时踩中）。两事件同时触发时 `parseHash` 幂等，跑两遍无副作用。
- **mk% Chrome 通知点击带聚焦**：`nav.rtFocus='market'` → 实时页滚到「今日盘面异动」；挂在其它页面时点击进实时页，
  挂载时消费一次（只靠 watch 会丢）。

**个人监测 / 提醒**

- **持仓区新增「今日盘中提醒」块**：Chrome 通知是瞬时的，错过即不可见；现在按 `risk.alerts.view` 权限渲染当天
  `it%` 告警列表（时间 + 标题正文，点行进详情），WS 刚推过的提醒立即补进列表。无权限不渲染，布局自适应。
- **雷达快照标注数据所属交易日**：盘前/休市日腾讯批量快照回退上一交易日，页面上「更新 22:16」却全是周五的数——
  后端 `/api/stock/radar` 增加 `data_date`（`radar_data_date`：快照 trade_date 取最新），快照不是今天时表头标
  「显示 X（最近交易日）数据」（与盘面 `data_date` 同口径）。
- **刷新间隔如实标注**：表头「15s 刷新」是写死的，收盘后实际 60s——改为按 `pollDelay` 当前档位显示。
- **缺值不上色**：雷达表 `pctCell` 与持仓行涨跌/浮盈对 null 判 `>= 0` 落涨色（`null >= 0` 为 true），
  「—」配红/绿会误导；改为 null 不上色（与 `chgCls` 同一条规矩）。
- **seq 守卫 + 重试节拍**：雷达/候选/提醒拉取加 seq（手动刷新与轮询并发时旧响应不得覆盖新响应）；
  盘面首拉失败时按本地时段兜底（交易时段 15s 重试，不再一失败就睡 60s）。

**宏观 / 口径**

- **机会区与实时闸门的口径矛盾要注明**：候选 `allowed` 是日频口径，决策线实时闸门是盘中口径，同屏可能一边
  「警戒」一边「可以找买点」（v3.26 决策：不改候选行为）——allowed 且实时闸门 closed/caution/unknown 时，
  机会区顶部加一行 `opportunityGateNote` 注明「开仓前以决策线结论为准」。
- **盘面宽度行标口径**：涨停/跌停是新浪快照阈值近似（含盘中触板）、炸板是东财涨停池口径（封住家数），
  design/13 §5.4 两者天然不相等，混在一行加 title 说明来源，避免「数字对不上」被当 bug 报。

**时区口径（v3.27.1 §10.9 规矩的补课）**：`market_sentiment.get` 的 stale/asof 判定、`buy_check` 的盘中价
「是否今天」判定与 bars/回补窗口、`risk.py` 两处告警归属 `trade_date`，原先都用主机时区 `date.today()`——
UTC 主机在北京 00:00–08:00 会把今天算成昨天（stale 恒真、盘中触发整段失效、告警记错日期）。统一改为
`_bj_today()`（`datetime.now(CST)`），各模块新增回归测试；既有用例的 `date.today()` 一并改为模块自身的
`_bj_today()`，测试在 UTC 主机上也能守住口径。

## 10. 多用户归属矩阵（v3.29.1 增补，2026-11-28）

逐一盘点页面上每个模块的数据归属——哪些是全市场共享、哪些按用户隔离、支持会话看到什么。
前端分区渲染已按权限二次控制（§5），本节补**数据层**的归属与本次修掉的缺口。

### 10.1 归属总表

| 模块 | 数据端点 | 归属 | 隔离机制 |
|---|---|---|---|
| 决策线·时段/数据日期/宽度摘要 | `GET /api/market/realtime` | **全局** | 后台线程单份内存缓存 |

### 10.2 本次修掉的缺口（v3.29.1）

1. **`GET /api/buy/check`、`GET /api/buy/candidates` 曾给被查看用户落交易计划**：两个端点都是 GET，
   `candidates()`/`check()` 内部 `intraday_state`/`trade_intraday.check` 默认 `persist=True`，
   会一路走到 `get_or_create_plan` 写 `trade_plan`——支持模式借身份查看时等于**查看即写入他人账户**，
   违反 `trade_intraday` 里写明的「GET 请求不得产生 INSERT/UPDATE」承诺（`/api/stock/radar` 早已
   按 `persist=not principal.support_mode` 传参，buy 端点漏了）。修复：`persist` 参数贯穿
   `trade_intraday.check → _build_state`、`buy_check._risk_gate → intraday_check`、
   `buy_check.check/candidates → intraday_state`，API 层统一 `persist=not principal.support_mode`。
   注意：**普通用户 GET 仍会落计划**（既有产品行为：打开页面即生成当日计划/教练），本次只收紧
   「支持模式代看不能写」这条底线，不改变普通用户的可见行为。
2. **雷达空关注池与快照失败区分**：新用户（无持仓无自选）看到「关注池暂无实时快照」会以为系统坏了。
   `/api/stock/radar` 增加 `pool_empty`，前端空态改「自选与持仓都是空——先去个股页加自选或导入持仓」，
   与真正的快照失败（稍后自动重试）分开。

### 10.3 已知边界（记录，不属缺陷）

- **关注池扫描上限 50**：`/api/stock/radar`、`buy_check._focus_pool` LIMIT 50（`intraday_watch`
  池加载无上限）。大自选用户的候选/雷达扫描范围受限；扩容前先压测腾讯批量快照与候选扫描耗时。
- **今日盘中提醒块挂在持仓区内**，随 `research.radar.view` 二次控制——同时缺 radar.view 的自定义角色
  看不到提醒块（默认角色矩阵不会出现该组合；提醒数据本身走 `risk.alerts.view`，与 radar 无关）。
- **支持会话的 WS 收不到 data_user 的 it% 告警**（`_alert_visible` 对个人行只发 row owner）——
  支持人员看「今日盘中提醒」列表需等轮询/手动刷新，不实时。
- `intraday_watch` 对**全部 active 用户**逐个评估（个人规则默认启用）：空池用户一轮只多几次
  `v_focus_pool` 查询，零外部请求，多用户成本可控。
