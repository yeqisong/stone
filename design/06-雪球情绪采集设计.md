# 06 - 雪球情绪采集设计（常驻轮询 · 帖子级增量 · 散户情绪特征）

> 版本：v1.0（2026-09-21，规划确认稿，未实施）
> 目标：每日全市场（~5400 只）拉取雪球个股讨论帖的**当日增量**，形成日内时间序列情绪数据，为 P3 的情绪特征（评论脉冲 / 看涨比）与 Alpha 建模供数。
> 姿态：**常驻轮询进程 + 全局预算调度**，不是每晚集中抓取，也不是高并发轰炸。
>
> **状态**：设计已与用户逐点确认（见 §2 决策记录），P0 标定未开工。

---

## 1. 可行性结论与请求数学（为什么不是"并发 5000"）

- 雪球核心接口（个股讨论列表族）强制 `xq_a_token` cookie；频控按 token 与 IP 双维度，阈值不公开、**必须实测标定**（P0）。
- 总量约束：单 token 约 2~3 req/s，token 池 3~4 个约 6~10 req/s 预算。
- **并发 5000 被否决**：全市场一轮仅需 ~1.1 万请求，5000 在途请求是攻击级速率，秒级封禁且法律上站不住，对目标零增益。
- **每股独立循环被否决**：5400 个各自随机 sleep 的循环，全局速率只"平均合规"，单股翻页/重试叠加时瞬时击穿不可控。改为**集中调度：全局令牌桶 + 到期堆**，瞬时速率恒在预算内。
- 分档轮询的稳态速率（盘中）：

| 档位 | 初始规模 | 盘中周期 | 初始分层依据 |
|---|---|---|---|
| T1 热 | ~500 只 | 15 分钟 | 成交额 top + 雪球关注数 |
| T2 中 | ~1500 只 | 60 分钟 | 同上 |
| T3 冷 | ~3400 只 | 4 小时 | 长尾自动落此档 |

稳态合计 ~1.2 req/s，红线 3~5 req/s 留足翻页与重试余量。
- 存储：5~6 万帖/天，清洗后单行 ~1KB → **20~30GB/年**，`xueqiu_status` 按年分区（对齐 feature_values 惯例）。

## 2. 已拍板决策记录（2026-09-21 与用户确认）

| # | 决策 | 内容 |
|---|---|---|
| D1 | 范围 | **第一期只做帖子级**（status 列表），不做帖下评论（两级结构请求量爆炸）；"资讯"新闻流放第二期 |
| D2 | 调度形态 | **全局令牌桶 + 到期堆集中调度**，随机抖动打散请求指纹；不做每股独立循环 |
| D3 | 档位 | T1/T2/T3 = 15min / 60min / 4h，初始按成交额+雪球关注数分层，**自适应升降档** |
| D4 | 进程形态 | **独立常驻进程**，不进主 DAG、不挂 cron 一次性任务；雪球故障与行情链路完全隔离 |
| D5 | 兜底轮 | 每晚 **23:30** 补漏（与 00:05 补数 cron 错峰）+ 日终统计 |
| D6 | 冷启动 | **只建游标不回补历史**：首日全市场扫一遍列表第一页建立基线，数据从上线日起累积（雪球列表翻页深度有限，接受） |

## 3. 总体架构

```
配置（.env: XUEQIU_TOKENS；strategy_config: 速率/档位参数）
        │
        ▼
【xueqiu_poller · 独立常驻进程】
 │
 │  时段引擎   ←─ trade_calendar（交易日/时段判定，驱动速率曲线）
 │  分档引擎   ←─ stock_master（全市场清单）+ 每日成交额
 │  到期堆     （每股一个 next_due_at，带随机抖动）
 │  令牌桶     （全局 QPS 红线 3~5 req/s，瞬时也合规）
 │  XueqiuGuard（token 池轮换 / 指数退避 / 熔断 / 健康缓存）
 │  写缓冲     （满 200 条或 60s 攒批 UPSERT）
 │
 ├──HTTPS──→ 雪球个股讨论接口（xq_a_token cookie）
 │
 └──写入──→ PostgreSQL
             ├─ xueqiu_status      （帖子，status_id 主键，按年分区）
             └─ xueqiu_crawl_state （游标 / 档位 / next_due_at / 健康态）
                        │
                        ▼
             FastAPI 状态页卡片 + WS 进度（复用现有通道）
                        │
                        ▼  （P3，后续）
             KEPL 情绪特征：xq_comment_cnt_1d / xq_bull_ratio / 盘中脉冲
```

与现有系统的关系：
- **不触碰主链路**：行情 DAG / tushare / baostock / feature_compute 全部不动；雪球侧任何故障最多损失当天情绪数据。
- **复用**：trade_calendar（时段判定）、stock_master（股票清单）、risk_alerts 表与 WS/Chrome 通知通道（熔断告警）、状态页配额卡片模式（监控卡片）、writers 的 UPSERT 幂等模式。
- **不进 TaskManager**（其并发 ≤5 是任务级语义，不适配常驻进程）；不注册 DAG 节点。

## 4. 核心设计

### 4.1 主循环（已确认稿）

```
【启动】
  ├─ 加载配置 → token 池初始化 + 健康探测
  ├─ 从 xueqiu_crawl_state 恢复游标 / 档位 / 到期堆
  └─ 首次运行（冷启动）：全市场扫一遍列表第一页，只建立游标基线

【主循环】每 tick：
  ① 时段判定（trade_calendar + 本地时钟）
  │     交易日 09:15–15:30 → 100% 速率
  │     交易日 15:30–23:00 → 50%（盘后讨论活跃）
  │     交易日 23:00–08:30 → 停（主调度休眠）
  │     非交易日全天       → 20%
  ▼
  ② 从到期堆取 next_due_at ≤ now 的股票（随机抖动打散顺序）
  ▼
  ③ 令牌桶有余量？──否──→ 等待下个 tick（绝不击穿红线）
  │ 是
  ▼
  ④ 拉该股讨论列表第一页（count=20，池中 token 轮换）
  │
  ├─ 成功：
  │    ├─ 对比游标算新增；新增 > 20 → 翻页直至游标（单轮上限 5 页保护）
  │    ├─ 新增帖子 → 写缓冲（攒批落 xueqiu_status）
  │    ├─ 更新游标；next_due_at = now + 档位周期 × 0.8~1.2 随机抖动
  │    └─ 自适应调档：连续 3 轮零新增 → 降一档
  │                    连续 2 轮新增 ≥ 1 页 → 升一档
  │
  └─ 失败：
       ├─ 网络超时 → 指数退避，next_due_at 后移，不阻塞其他股票
       ├─ 429 / 风控错误码 → 退避 + 换 token 重试
       ├─ 单 token 连续失败 ≥5 → 标记不健康，移出池
       └─ token 池耗尽 → 全局熔断：暂停调度 + risk_alerts 告警
                          + 定时探测恢复或人工补 token

【兜底轮】每晚 23:30：只重访当日失败/被退避股票，出日终统计
【恢复】进程重启：直接从 crawl_state 续跑，无人工介入
```

### 4.2 调度器（集中式，D2）

- **到期堆**：小顶堆按 `next_due_at` 排序，tick 时弹出到期者；`next_due_at = now + 档位周期 × U(0.8, 1.2)`，随机抖动既打散请求指纹又避免整档同步到期。
- **令牌桶**：全局单桶，速率 = 红线 × 时段系数。所有请求（轮询/翻页/重试/token 健康探测）从同一桶取令牌，互相挤兑但永不击穿。
- **时段引擎**：读 trade_calendar 判交易日，本地时钟判时段，输出速率系数（100% / 50% / 20% / 停）。

### 4.3 分档与自适应（D3）

- 初始分层：成交额 top（T1），关注数与成交额混合（T2），其余 T3；P0 前 tushare 无雪球关注数，首版可用成交额单独分层，关注数字段若接口可得再引入。
- 自适应（阈值 P1 实测后调整）：`zero_streak ≥ 3` 降一档；`full_streak ≥ 2`（连续整页新增）升一档。档位持久化在 crawl_state，重启不丢。
- 兜底约束：T3 周期下限 = 4h（交易日内至少覆盖一轮），防止全部沉底。

### 4.4 XueqiuGuard（token 池 / 频控 / 熔断）

对标 TushareQuota 的角色定位，但逻辑不同（滑窗限速而非次/天计数）：
- **token 来源**：匿名 cookie（访问首页获取，易得、配额低）+ 可选小号登录 token（耐久）。`.env: XUEQIU_TOKENS` 逗号分隔，运行时可热加载补充。
- **健康度**：连续失败 ≥5 移出池，定时探测回归；单 token QPS 与全局 QPS 双重上限。
- **退避**：429/风控码指数退避（1s/2s/4s/…封顶 10min）+ 换 token 重试。
- **熔断**：池空 → 暂停整个调度器 + risk_alerts 告警（kind='xueqiu_circuit'），定时探测恢复。

### 4.5 数据模型（DDL 草案，实施时进 `app/db/schema.py` 幂等迁移）

`xueqiu_status`（帖子，按年 RANGE 分区，对齐 feature_values 惯例）：

| 字段 | 类型 | 说明 |
|---|---|---|
| status_id | BIGINT PK | 雪球帖子全局 ID，UPSERT 幂等键 |
| code | VARCHAR(12) | 关联个股 |
| user_id | BIGINT | 发帖用户（去标识化可选，仅存 ID） |
| text_raw / text_clean | TEXT | 富文本原文 / 清洗后（剥 `$股票$` `#话题#` HTML） |
| mark | SMALLINT | 看涨/看跌标记，枚举语义 P0 确认；**散户情绪直接指标** |
| created_at | TIMESTAMPTZ | 发帖时间（北京时间） |
| view/like/retweet/reply_count | INTEGER | 拉取时刻快照，末次更新为准 |
| source | VARCHAR(32) | Android / iOS / Web |
| fetched_at | TIMESTAMPTZ | 本系统采集时间 |

`xueqiu_crawl_state`（调度状态，每股一行，~5400 行）：

| 字段 | 类型 | 说明 |
|---|---|---|
| code | VARCHAR(12) PK | |
| tier | SMALLINT | 当前档位 1/2/3 |
| last_status_id | BIGINT | 游标：已见最大帖子 ID |
| next_due_at | TIMESTAMPTZ | 到期堆持久化 |
| zero_streak / full_streak | INTEGER | 升降档计数 |
| fail_streak | INTEGER | 退避依据 |
| today_status | VARCHAR(16) | ok / degraded / failed（兜底轮筛选依据） |
| last_ok_at / updated_at | TIMESTAMPTZ | |

### 4.6 写缓冲

轮询回的新增先进内存缓冲，**满 200 条或 60s** flush 一次批量 UPSERT——避免 5400 次轮询产生 5400 个小事务；进程退出前强制 flush；崩溃丢失上限 = 缓冲窗口内增量（可接受，兜底轮会重扫当日窗口补齐）。

### 4.7 监控

状态页新增卡片（复用 tushare_quota 卡片模式）：实时 QPS / 各档位覆盖进度 / token 健康 / 今日新增帖数 / 熔断状态；进度经 WS 推送（type='xueqiu_status'）。

| 阶段 | 内容 | 出口条件 |

| **P3 特征化** | KEPL 派生：`xq_comment_cnt_1d`、`xq_bull_ratio`（mark 涨跌比）、5 日增量、盘中脉冲；后续可接 LLM 情绪打分 | 特征入库 + Alpha 侧实验 |

## 6. P0 标定任务清单（实施第一步）

1. **端点确认**：个股讨论列表接口可用形态（候选：`/statuses/stock/list.json`、`/query/v5/symbol/quote/status/list.json`），字段映射到 §4.5。
2. **token 获取与存活**：匿名 cookie 获取流程脚本化；有效期实测（小时/天级）。
3. **频控边界**：单 token 从 0.5 req/s 逐级加压至首次 429/风控错误码，记录阈值与封禁恢复时间。
4. **常驻低速存活**：1 req/s 持续 2h，观察是否被行为画像封禁（常驻模式比一次性高压更需验证）。
5. **mark 枚举**：看涨/看跌/无标记的取值语义确认。
6. **翻页深度**：热门股列表可翻页上限（决定冷启动与爆发股覆盖能力）。

产出物：`strategy_config.xueqiu` 默认参数（全局红线 / 档位周期 / 时段系数）+ 本文档回填实测值。

## 7. 风险清单

| 风险 | 对策 |
|---|---|
| token 封禁/失效（最脆弱一环） | 池化 + 热加载 + 健康探测 + 熔断告警（复用 risk_alerts WS/Chrome 通道） |
| 接口改版（雪球历史上改过几版端点） | adapter 单点隔离 + 启动健康检查 + P0 端点确认前置 |
| 常驻模式被行为画像 | 随机抖动 + 时段化频率 + 总预算红线（已内置于调度器） |
| 数据噪音（广告/水贴/转发） | 入库前基础过滤规则（P1 观察样本后定） |
| 合规边界 | 个人研究自用、控频、不绕付费墙、不对外重分发——四条守死；本设计控频即为红线设计 |
