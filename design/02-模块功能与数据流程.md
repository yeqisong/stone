### 1.2 db/connection.py — 双引擎

- `async_engine`（asyncpg）：FastAPI 依赖注入 `get_db()`；prod pool=5 / dev=1。
- `sync_engine`（psycopg2）：crawler/scripts/后台线程用 `get_sync_db()`；pool=5, overflow=10。

### 1.3 task/manager.py — TaskManager 统一任务机制

线程安全单例。**所有长任务**（DAG 流程 / 补数 / 特征计算 / 统计 / 模型训练）的进度跟踪中枢：

- **并发控制**：全局 `MAX_CONCURRENT=5`；`_flow_locks[flow_id]` 同流程互斥（重复触发→429）。
- **Task / TaskNode**：`task-{uuid8}`，节点状态机 `pending → running → success/failed`，携带 log_id（关联 dag_run_log）、progress_pct、rows、detail、error。
- **流转 API**：`create_task → start_task → update_node（自动算总进度）→ complete_task / fail_task（释放锁 + 唤醒 WS）`。
- **启动自愈**：heartbeat 超 5 分钟的 running 日志标 failed（"服务器重启，任务中断"）。

### 1.4 app/signal.py — 线程↔协程桥梁

`asyncio.Event` + 主循环引用：后台线程（DAG/补数/特征）通过 `call_soon_threadsafe` 唤醒 WS 广播协程，实现事件驱动 + 超时兜底（运行 2s / 空闲 30s）。另含任务终止信号（`_stop_requests` set + per-run threading.Event）。

### 1.5 app/ai/ — DeepSeek Function Calling

- `deepseek_client.py`：OpenAI 兼容；Key 回退读 strategy_config.global_preference.params.deepseek_key；连败 3 次降级为快捷菜单。
- `tools.py` 8 个工具：get_my_portfolio / get_stock_detail / get_buy_signals / get_data_status / get_strategy_config（query 类直连 DB）；confirm_add_portfolio / confirm_set_preference（write 类**只生成确认卡片不落库**）；trigger_recalculation（admin）。

### 1.6 app/feishu/ — 飞书 Bot

`POST /webhook/feishu`：challenge 应答 → HMAC-SHA256 签名校验 → 文本消息走 AI 对话（系统上下文注入实时持仓/信号/数据状态）→ tool_calls 执行 → write 类返回 interactive 确认卡片 → **用户点卡片按钮**才真正落库（confirm_add：UPSERT portfolio + history；confirm_preference：读后 merge 更新偏好，保留 deepseek_key）。

### 1.7 app/kepl/ — 表达式解析器

Lark LALR(1)：`+-*/`、括号、NUMBER/BOOL/CNAME → KepLAST（FieldRef/NumLit/BoolLit/FuncCall/BinOp）。函数分两类：**TIME_SERIES**（ma/ema/rsi/std/atr/roc/bias/pct_change/dif/dea/macd_hist/boll_*/corr/sma/obv）与 **CROSS_SECTIONAL**（avg/sum/max/min/rank/quantile/zscore）。

### 1.8 strategy/indicators.py — 技术指标

纯 numpy/pandas：sma/ema/**rsi**（除零处理：严格上涨=100、横盘=50）/**bollinger_bands**（ddof=0 总体标准差，对齐通达信/TA-Lib）/macd/atr/obv/周月聚合。

## 2. crawler/ 采集层

### 2.1 adapters/ — 数据源抽象

- `base.py`：标准化 dataclass（KlineRow/IndexKlineRow/FundamentalRow/StockInfo，volume=股、amount=元）；`DataSourceAdapter` 抽象基类 7 方法；`code_to_exchange`（6→SSE，0/2/3→SZSE，4/8/9→BSE）。
- `manager.py`：DataSourceManager — priority 升序注册（tushare=5 → baostock=20，AKShare 已于 v3.2 删除），`check_all_health()` 带 300s TTL 缓存，`get_source()` 返回首个健康源，`fetch_with_fallback()` 异常自动切换。
- `tushare_adapter.py`：限流 1.3s/次；K 线双路径（短区间按日期全市场 / 长区间按股票 100 只/批）；`_enrich_kline_batch`（50只/批 daily_basic+adj_factor）补 **close_hfq=close×复权因子** 与 turnover；北交所 `.BJ` 映射；基本面 daily_basic 按最近工作日全市场拉取；另含 top_list/moneyflow/hk_hold/margin_detail/holder_number 扩展方法（**未接入链路**）。
- `baostock_adapter.py`：串行拉取（单 TCP 非线程安全）；K 线两次查询合并（adjustflag=3 不复权 OHLCV+turn → adjustflag=1 后复权 close）；`download_fundamentals` 的 trade_date 取**数据最新交易日**（与 tushare 最近工作日口径对齐，避免周末双行）。

#### 两数据源字段协作约定（v3.2 复盘结论）

| 表 | 协作机制 |
|---|---|
| **daily_quote** | 两源均输出：close（不复权）、close_hfq（tushare=close×adj_factor / baostock=adjustflag=1）、close_qfq=close、volume=股（tushare vol×100）、amount=元（tushare×1000）、turnover。UPSERT 逐字段覆盖；`close_hfq` 为 NULL/0 时保留库内旧值；真实数据行 `is_suspended=false` 清除旧停牌标记。**已知限制**：ETF 后复权仅 baostock 路径支持（tushare fund_adj 接口积分要求高，fetch_etf_kline 的 close_hfq=close） |
| **stock_fundamentals** | 主键 (stock_code, trade_date)，UPSERT **逐字段 COALESCE 防空值覆盖**：tushare 写满 22 字段（daily_basic 全量），baostock 只写 9 字段（PE/PB/ROE/营收净利/股本/市值/行业）→ 任一源先写都不丢数据，缺失字段由另一源补充。tushare 的 total_share/total_mv 精确；baostock 的 total_shares 为 vol/(turn%) 估算（COALESCE 下 tushare 值优先保留）。**trade_date 两源统一为数据最新交易日**。market_cap 缺失时 writers `_enrich_market_cap` 从 daily_quote 补全 |
| **stock_master** | 唯一实现 = `BackfillManager._run_stock_master`（补数按钮与 DAG stock_master 节点复用同一函数）：`code_to_exchange` 推断 + COALESCE 防 NULL 覆盖 + 全字段（delist_date/is_hs/act_name/area/industry/reg_capital/employees/main_business）+ 退市标记。旧 pipeline 独立实现已删除（曾把 000/001/002/003 误标 SSE、ipo_date 被 NULL 覆盖） |

### 2.2 backfill.py — BackfillManager 历史补数

单例 + 全局单任务锁。任务类型：`kline / index / etf / fund / calendar / stock_master`（indicator 已废弃）。

**K 线补数核心机制**：
- 断点续传：force→空跳过集；单日→查当日 DISTINCT code 跳过已有；多日→靠 UPSERT 幂等。
- 自适应并发：内存 >90% 批次-1 / <70% +1（上限用户 batch_size）；每批 ThreadPoolExecutor(1) + 180s 轮询超时（轮询中持续写心跳 + WS 推进度）。
- 跨年分段：区间 >365 天按自然年拆分；失败自动 relogin 重试一次。
- **停牌标记**：仅批次拉取成功时，缺失且已上市（ipo≤end）的股票写 `is_suspended=true` 全零行；失败批次不写（防止断点续传永久跳过）。
- 重启自愈：running/cancelling 孤儿任务标 failed。
- fund 补数：`fetch_fundamentals(None)` 全市场 → `writers.batch_upsert_fundamentals`（与 DAG fund 节点同一写入路径，含市值补全）→ 行业跨表回写 stock_master。

### 2.3 writers.py — 批量 UPSERT

`batch_upsert_kline`（**真实数据 is_suspended=false 清旧停牌标记；close_hfq 空值保留库内旧值**）、`batch_upsert_index_kline`、`batch_upsert_fundamentals`。

## 3. scripts/ 调度层

### 3.1 dag.py — DagExecutor 计划-执行模型

- **计划阶段** `prepare_context`：run_id → 节点集（起点+全部下游，非集合内预置 completed）→ Kahn 拓扑排序（检环）→ 每节点 INSERT dag_run_log(pending) 取 log_id → 组装 context。
- **执行阶段**：循环找依赖就绪层 → 并行执行；失败节点也标 completed（下游继续不卡死）；每步检查终止信号。
- force 仅对无依赖入口节点生效（bool 或 per-node dict）。

### 3.2 pipeline.py — 节点函数注册表 NODE_FN_MAP（14 节点）

| 节点 | 写入表 | 说明 |
|---|---|---|
| cron | dag_run_log | 纯标记节点（每个流程强制含 1 个） |
| stock_master | stock_master | 全量列表 UPSERT + 标退市（含指数/ETF） |
| kline | daily_quote | baostock 源走 BaostockCrawler 高速路径，否则适配器 |
| index / etf | index_daily_quote / daily_quote | 同上双路径（ETF 代码段 15x/5x） |
| fund | stock_fundamentals | 双路径；行业回写 stock_master |
| treemap | stock_treemap_cache | 4 指标（mcap/volume/amount/pe）三层树 |
| stats | data_stats_cache | generate_stats 全库统计（避免实时 COUNT） |
| daily_completeness | daily_completeness | 当日四类行数 + baseline |
| entity_stats | entity_stats | 首次 JOIN 基线，之后增量（SSE 日历为基准） |
| feature_compute | feature_values | 增量近 10 天 / force 全量 2020-01-01 |
| feature_backfill | feature_values | 全量 2020-01-01 起 |
| model_signal | signal_history | 取 ACTIVE 版本规则评分（见 §4.d） |
| model_health | signal_history + model_health | forward 回填 / 止损了结 / 胜率分档 |

**日志基础设施**：`write_node_log`（pending INSERT / running 更新 / 终态写 rows+finished）；`_hb_thread` 心跳（25s 更新，**5 分钟 rows 无进展判超时 failed**）。

### 3.3 feature_compute.py — KEPL→pandas 引擎

- `_extract_lookback(公式)`：ma/pct_change→N，ema/rsi→2N，boll→20，dif/dea/macd_hist→35，bias→max(N1,N2)。拉取起点 = start − max(lookback×2, 10) 天（下限 2020-01-01），**保证滚动窗口有历史、增量计算不漂移**。
- 执行双路径：常用公式正则快路径 → 否则 parse_to_tree + `_execute_ast` 递归（时间序列 `groupby(stock_code).transform()`；截面 rank=同日分位 / zscore=同日标准化；自定义函数 RestrictedPython 编译缓存）。
- 大区间自动分片（30 天/片，单片失败不影响已完成片）。
- **写入**：独立 raw connection，`DELETE 范围 + COPY FROM STDIN`（CSV 流式，任意行数不 OOM）。

### 3.4 cron_scheduler.py — 定时触发

60s 扫 `dag_flows WHERE status='published' AND cron_expr`：croniter 判到期（<70s 窗口）+ **last_run_at 幂等**（同一 cron 周期只触发一次）→ `_execute_flow_internal` → UPDATE last_run_at。

## 4. 核心数据流

### 4.a 每日定时采集（cron → 节点 → WS）

```
[cron_scheduler 60s]
 └─ 扫 dag_flows 到期（last_run_at 幂等）
     └─ _execute_flow_internal(flow_id, trade_date=今天)
         ├─ TaskManager.create_task（全局≤5 / 同flow互斥）
         ├─ 临时 DagExecutor（nodes ← dag_flows.nodes，fn ← NODE_FN_MAP）
         └─ 后台线程：prepare_context（写 pending 日志→log_ids）
             └─ 逐节点：依赖就绪 → tm.update_node(running)→WS
                 → node.fn（write_node_log + 心跳 + 采集/计算 + UPSERT）
                 → tm.update_node(终态)→WS
             → 全成功 complete_task / 任一失败 fail_task

[WS 广播协程]（事件驱动：_wake / 超时兜底 2s|30s）
  推送：dag_status · dag_log · task_progress · backfill_progress
        · feature_compute_progress · sys_metrics(30s)
```

### 4.b 历史补数（状态页按钮）

```
POST /api/data_status/backfill {type, start, end, force, batch_size}
 └─ BackfillManager.start（单任务锁→Busy 429）
     └─ 后台线程：读 stock_master 全量代码（含退市）
         → 逐批（自适应并发/跨年分段/180s超时轮询）
         → fetch_fn → writers.batch_upsert_*（UPSERT）
         → 成功批次：缺失且已上市 → 停牌标记
         → 每批 UPDATE backfill_tasks + WS backfill_progress
```

### 4.c 特征计算

```
features 表（KEPL 公式, target_entity, status=enabled）
 触发：DAG feature_compute/feature_backfill 节点 或 POST /features/{id}/compute-range
 → 拉取起点 = start − max(lookback×2,10) 天
 → _fetch_ohlcv（JOIN stock_master 按类型过滤, float32）
 → 正则快路径 | KEPL AST 递归（时序 transform / 截面 rank·zscore / 自定义函数）
 → 分片（30天/片）→ DELETE 范围 + COPY → feature_values
 → 回写 features 质量列（完整度/缺失格/最近计算日；<0.6 标 data_anomaly）
```

### 4.d 模型生命周期

```
状态机：DRAFT → TRAINING → PENDING → ACTIVE ⇄ ARCHIVED
                        └──→ REJECTED ←─┘(拒绝后可 retrain)
① 创建 POST /v1/models → 自动版本 v{max+1}.0（数值比较）
② 预检 GET /feature-check → 60/20/20 三阶段覆盖统计，缓存 config._feature_check（存表）
③ 训练 POST /train → TaskManager(model_train) + TRAINING
   → build_feature_wide_table（长表 PIVOT + close_hfq）→ 新鲜度断言
   → 特征工程（bias/vol_ratio/沪深300动量）→ Triple Barrier 标签(±10%/-5%, 10d/20d)
   → Optuna TPE XGBoost 双周期（每轮 UPSERT training_trials）
   → 测试集 _backtest（资金/流动性/整手/佣金印花税滑点约束）
   → 模型文件 data/models/{v}/xgb_{10d,20d}.pkl → PENDING + 指标
④ 评估 diagnosis / attribution（三基线 + Brinson）
⑤ 激活 approve → 同 entity 旧 ACTIVE→ARCHIVED
⑥ 信号 DAG model_signal 节点：ACTIVE 版本 + 偏好阈值(left/balanced/right)
   → 规则评分（BOLL 超卖/RSI 超卖/MACD 正柱 ≥ buy_score_min）
   → DELETE 当日旧 → INSERT signal_history（含 params_snapshot）
⑦ 健康 DAG model_health：回填 forward_{5,10,20}d → 止损了结(status=closed)
   → 胜率分档 HEALTHY/CAUTION/WARNING/CRITICAL → model_health
```
